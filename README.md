# 电商图片制作 skill · 1.0.0

支持完整制作或单独阶段；按产品名和图片编号定位文件。分发包不含作者商品、参考图库、密钥或测试图片。

## 安装

解压后将整个 `ecommerce-image-workflow` 文件夹放入宿主的技能目录。Codex通常为 `~/.codex/skills/`；遵循使用者实际环境的技能发现机制。不要把文件夹内文件逐个拆散。无需仓库规则。

包内包含流程、模板、文件脚本及三份MIT依赖：poster-style-transfer、ecommerce-visual-copywriting和完整ecommerce-image-skills集合（含12个技能）。白底技能amazon-white-background已内置，无需单独安装；完整制作仍需单独安装detail-flow。来源、版本和职责见 [依赖说明](references/dependencies.md)，不会自动下载缺失技能。集合内置不等于执行全部技能，当前流程只调用其中所需的白底技能。

内置技能也已登记上游来源、仓库内路径和更新定位规则，见 [依赖来源与更新说明](references/dependencies.md)。以后可直接说“更新内置 poster-style-transfer”或“更新内置 ecommerce-visual-copywriting”；执行者据此检查上游并更新本仓库对应 `bundled/` 副本，不自动修改宿主安装副本。

文件检查、等比导出、预览和项目记录依赖Python3和Pillow：已有依赖直接复用，缺少时对所选解释器执行 `python -m pip install -r <本技能目录>/scripts/requirements.txt`。正式流程只使用本仓库的Pillow文件工具；技能本身不提供生图账号或服务。

## 使用

无品牌框 / 有品牌框两套可复制指令见 [提示词模板](references/prompts.md#简短用户指令)。常用无模板写法：

```text
使用 $ecommerce-image-workflow，完整制作商品主图和详情图。
商品目录：…
范围：全部产品
参考库：…
```

有模板时在指令中加 `模板：…`（填文件夹，与参考库相同；不必标注壳/示意，由执行者识别；技能仓库不存放你的模板文件）。

商品目录、参考库由用户提供，名称和位置不限，已在上下文明确时不必重复。项目默认输出到商品根目录同级的 `输出结果/`，非空则新建带时间的目录，特殊位置才补充项目输出目录；每套公共参考缓存位于该参考套系的 `_参考缓存/`。继续或返修才恢复原项目，完整重跑新建输出，不因发现旧文件夹就自动续做。完整定位规则见 [制作规范第2节](references/workflow.md#2-输入及目录)。

只做一类图片时，将第一句换成：

- `使用 $ecommerce-image-workflow，仅制作商品主图。`
- `使用 $ecommerce-image-workflow，仅制作商品详情图。`

两种指令均包含该类图片所需的素材处理、参考分析、文案、生成、审核、必要返修和交付，不制作另一类图片。

### 分阶段指令速查

已有项目时，先写 `项目总目录：…`；当前对话已定位项目时可以写“继续当前项目”。以下指令均可补充商品名、主图或详情及编号来缩小范围。

完整制作有 `模板：` 时先模板前置，再全库参考前置；首次补齐参考分析，后续只更新缺失、变化或无效部分，再分派商品任务。模板前置与参考库前置均可单独执行。“分析参考”负责商品选套；修改指定文案是按需操作，不是审核后的必经阶段。

| 目的 | 可复制的指令 |
|---|---|
| 模板前置 | 使用 $ecommerce-image-workflow，仅做模板前置：校验模板并（如需）生成锁定 slots，写入模板旁 `_模板缓存/`，不生图、不跑参考。模板：…。 |
| 参考库前置 | 使用 $ecommerce-image-workflow，仅预分析整个参考库并更新公共选套索引，不生图。参考库：…。 |
| 整理商品资料 | 使用 $ecommerce-image-workflow，仅整理商品资料，不生图。 |
| 处理产品素材 | 使用 $ecommerce-image-workflow，仅制作商品白底和透明底素材。 |
| 分析参考 | 使用 $ecommerce-image-workflow，仅分析和选择参考，不生图。 |
| 策划文案 | 使用 $ecommerce-image-workflow，仅策划逐图文案和设计执行卡，不生图。 |
| 制作图片 | 使用 $ecommerce-image-workflow，使用已有执行卡和已验收素材，仅制作商品图片。 |
| 仅审核 | 使用 $ecommerce-image-workflow，仅审核现有图片，不返修、不生图。 |
| 返修指定图 | 使用 $ecommerce-image-workflow，仅返修商品A主图03，要求：…。 |
| 修改指定文案 | 使用 $ecommerce-image-workflow，仅修改商品B详情02的文案，要求：…，先不生图。 |
| 导出交付 | 使用 $ecommerce-image-workflow，仅导出已通过的图片并制作交付预览，不生图。 |

例如：`使用 $ecommerce-image-workflow，项目总目录：…，仅返修商品A主图03，要求：…。`

新项目提供商品目录、范围和参考库，输出位置可省略；各阶段只读取必要输入，缺项会列明，不自动扩成整套。图片制作阶段需要已有执行卡及已验收素材；缺失时不会静默补做。单独返修仍受历史返修额度限制。

首次生成项目索引后，后续按商品名和编号定位。新对话或换电脑无法定位项目名称时，只需提供项目总文件夹一次。分享项目需同时分享必要输入，索引不会让缺失图片自动出现。

交付文件夹最外层提供 `交付总览.md`：一张表查看所有产品主图、详情的已交付/应交付数量，直接列出缺失或待更新编号，异常明细说明原因；素材及预览缺项另列。不必逐个打开产品文件夹，返修后总览同步更新。

交付前包含收尾整理：清理本轮已成功且无后续依赖的临时清单和编排脚本，重复记录先归入索引再清理；失败待恢复的保留。实际生图提示词、原件、返修版、当前执行卡和公共参考缓存保留，不清空工作目录。

## 维护

执行时集中检查环境和项目，只对实际变化重查；定向追加直接定位相关图。每张图先完整审核再汇总返修，减少分散修补。文件归档、JSON更新、阶段计时及交付总览改用清单文件驱动的固定工具，避免临时长命令；见 [文件工具说明](scripts/README.md)。这些改动不保证固定生图速度，实际收益需后续制作记录验证。

清单还可一次串联多张等比导出、尺寸检查、选版文件预览及编号核对；不必逐张发导出命令。脚本按项顺序执行，遇错明确记录并停止后续操作，不将整批误记为成功。

参考图的尺寸、指纹和分类总览由固定缓存工具批量准备，未变化就复用；商品文件清点及实际提示词留存也有固定批量入口。选套、产品适配和视觉审核仍由AI完成，见 [全流程批量操作检查表](references/batch-operations.md)。

商品保真要求通过固定条款、六类商品观察表和逐图设计组装，发送前校验原文及输入图片，减少不同测试把要求写得一详一略；见 [保真提示词组装](references/prompt-builder.md)。它约束输入完整性，不保证模型逐像素还原，仍需看图验收。

参考套系的总览与原参考分析默认缓存到该套系 `_参考缓存/`；参考库不能写入时，显式指定项目 `公共参考/` 的缓存位置，不自动切换。不在每个产品重复生成。脚本批量核对内容指纹，逐张列出新增、删除、修改和未变化项；AI只更新变化图片及受影响的公共结论，未变化且有效的分析复用。缓存记录原参考特点，各产品仍独立确定最终风格、配色和文案。已验收素材及记录在适用条件未变时复用；缓存和用户项目数据不提交到本仓库。

素材在生成后立即验收，透明底按实际使用效果判断，不为无明显影响的细边反复返修。项目记录以项目索引、产品索引和当前执行卡为主，避免重复拆分JSON；既有历史文件保留。

执行卡只维护当前版，不默认建立历史版本目录。每次生成和返修的实际完整提示词及调用参数逐图保存在工作目录“生图提示词”下，可查看当时是否写入尺寸要求；尺寸仅写提示词时会明确注明，不冒充工具已强制设置宽高。

本仓库根目录即技能根目录，移动时连同隐藏文件和 `.git`（初始化后）整体移动。商品与制作项目留在仓库外。

### 验证与打包

在仓库根目录运行（用实际可运行的Python解释器替换 `python`）：

```text
python tools/verify_package.py
python tools/verify_package.py --build
```

第一条验证元数据、包内引用和文件工具；第二条验证后生成 `dist/ecommerce-image-workflow-<VERSION>.zip`。压缩包固定包含一层技能文件夹，按允许清单打包，不带Git、开发工具、项目数据或历史ZIP。版本由 `VERSION` 管理，变化记入 `CHANGELOG.md`。上传GitHub时提交源文件，ZIP通过Release附件分发。

日常更新与正式发布分开：日常推送不升版本；用户明确要求发布时才更新版本、创建标签和GitHub Release。维护者按 [RELEASE.md](RELEASE.md) 的完整清单操作。

验证脚本不代替真实生图测试，也不包含官方skill校验器。本地首版尝试官方校验时缺少PyYAML且网络不可用，未宣称官方校验通过。

安装后的 `references/workflow.md` 是完整规则正文；`SKILL.md` 是入口；`references/prompts.md` 是模板；`scripts/` 是文件工具。发布源在这个技能文件夹，后续改动以此为准，不再与外部流程文档同时维护两套。更新后重新打包，接收者替换自己的技能目录；项目文件保留在安装目录外。

第三方原文件和许可证保存在bundled，不混入本技能的自主维护正文；详细来源见 `references/dependencies.md`。本版只做本地结构及文件工具检查，尚未用封装入口进行真实生图回归，不能将其描述为已验证整套成图效果。

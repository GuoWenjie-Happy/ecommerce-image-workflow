# 电商图片制作 skill · 1.0.0

支持完整制作或单独阶段；按产品名和图片编号定位文件。分发包不含作者商品、参考图库、密钥或测试图片。

## 安装

解压后将整个 `ecommerce-image-workflow` 文件夹放入宿主的技能目录。Codex通常为 `~/.codex/skills/`；遵循使用者实际环境的技能发现机制。不要把文件夹内文件逐个拆散。无需仓库规则。

包内包含流程、模板、文件脚本和两个MIT依赖。完整制作还需安装 `amazon-white-background` 和 `detail-flow`，来源及能力要求见 `references/dependencies.md`。本ZIP不是四个依赖全部预装的离线包，不会自动下载缺失技能。

文件工具依赖Python3和Pillow：已有依赖直接复用，缺少时对所选解释器执行 `python -m pip install -r <本技能目录>/scripts/requirements.txt`。技能本身不提供生图账号或服务。

## 使用

```text
使用 $ecommerce-image-workflow，完整制作商品主图和详情图。
商品目录：…
范围：全部产品
参考库：…
项目输出目录：…
```

只做一类图片时，将第一句换成：

- `使用 $ecommerce-image-workflow，仅制作商品主图。`
- `使用 $ecommerce-image-workflow，仅制作商品详情图。`

两种指令均包含该类图片所需的素材处理、参考分析、文案、生成、审核、必要返修和交付，不制作另一类图片。

### 分阶段指令速查

已有项目时，先写 `项目总目录：…`；当前对话已定位项目时可以写“继续当前项目”。以下指令均可补充商品名、主图或详情及编号来缩小范围。

| 目的 | 可复制的指令 |
|---|---|
| 整理商品资料 | 使用 $ecommerce-image-workflow，仅整理商品资料，不生图。 |
| 处理产品素材 | 使用 $ecommerce-image-workflow，仅制作商品白底和透明底素材。 |
| 分析参考 | 使用 $ecommerce-image-workflow，仅分析和选择参考，不生图。 |
| 策划文案 | 使用 $ecommerce-image-workflow，仅策划逐图文案和设计执行卡，不生图。 |
| 制作图片 | 使用 $ecommerce-image-workflow，使用已有执行卡和已验收素材，仅制作商品图片。 |
| 仅审核 | 使用 $ecommerce-image-workflow，仅审核现有图片，不返修、不生图。 |
| 返修指定图 | 使用 $ecommerce-image-workflow，仅返修山茶油主图03，要求：…。 |
| 修改指定文案 | 使用 $ecommerce-image-workflow，仅修改苹果详情02的文案，要求：…，先不生图。 |
| 导出交付 | 使用 $ecommerce-image-workflow，仅导出已通过的图片并制作交付预览，不生图。 |

例如：`使用 $ecommerce-image-workflow，项目总目录：…，仅返修山茶油主图03，要求：…。`

新项目按上方四项提供路径和范围；各阶段只读取必要输入，缺项会列明，不自动扩成整套。图片制作阶段需要已有执行卡及已验收素材；缺失时不会静默补做。单独返修仍受历史返修额度限制。

首次生成项目索引后，后续按商品名和编号定位。新对话或换电脑无法定位项目名称时，只需提供项目总文件夹一次。分享项目需同时分享必要输入，索引不会让缺失图片自动出现。

## 维护

参考套系的总览与原参考分析默认缓存到该套系 `_参考缓存/`，参考库不能写入时放到项目 `公共参考/`；不在每个产品重复生成。使用前核对原图内容指纹，有变化才更新相关缓存。缓存记录原参考特点，各产品仍独立确定最终风格、配色和文案。已验收素材及记录在适用条件未变时复用；缓存和用户项目数据不提交到本仓库。

素材在生成后立即验收，透明底按实际使用效果判断，不为无明显影响的细边反复返修。项目记录以项目索引、产品索引和当前执行卡为主，避免重复拆分JSON；既有历史文件保留。

执行卡只维护当前版，不默认建立历史版本目录。每次生成和返修的实际完整提示词及调用参数逐图保存在工作目录“生图提示词”下，可查看当时是否写入尺寸要求；尺寸仅写提示词时会明确注明，不冒充工具已强制设置宽高。

本仓库根目录即技能根目录，移动时连同隐藏文件和 `.git`（初始化后）整体移动。商品与制作项目留在仓库外。

### 验证与打包

在仓库根目录运行（用实际可运行的Python解释器替换 `python`）：

```text
python tools/verify_package.py
python tools/verify_package.py --build
```

第一条验证元数据、包内引用和文件工具；第二条验证后生成 `dist/ecommerce-image-workflow-<VERSION>.zip`。压缩包固定包含一层技能文件夹，按允许清单打包，不带Git、开发工具、项目数据或历史ZIP。版本由 `VERSION` 管理，变化记入 `CHANGELOG.md`。上传GitHub时提交源文件，ZIP通过Release附件分发。

验证脚本不代替真实生图测试，也不包含官方skill校验器。本地首版尝试官方校验时缺少PyYAML且网络不可用，未宣称官方校验通过。

安装后的 `references/workflow.md` 是完整规则正文；`SKILL.md` 是入口；`references/prompts.md` 是模板；`scripts/` 是文件工具。发布源在这个技能文件夹，后续改动以此为准，不再与外部流程文档同时维护两套。更新后重新打包，接收者替换自己的技能目录；项目文件保留在安装目录外。

第三方原文件和许可证保存在bundled，不混入本技能的自主维护正文；详细来源见 `references/dependencies.md`。本版只做本地结构及文件工具检查，尚未用封装入口进行真实生图回归，不能将其描述为已验证整套成图效果。

# 项目品牌框模板约定

模板由**用户自备**（指令里 `模板：` 填文件夹，与参考库写法相同）；**技能仓库不维护用户模板目录**。文件夹内以后还可放其它资源，不限于品牌框。非品牌框构图样式仍按制作规范迁移，不临摹原品牌/店招框。

用户指令写法：见 [提示词模板 · 有模板](prompts.md#有模板)。用户**不必**在指令里写「无卖点壳／有卖点示意」等标签。

## 什么是品牌框

店招顶栏、底栏壳、整圈外框、官方角标壳等可复用身份层（颜色不限）。  
不算品牌框：产品、场景、代言人、本品主副标题、规格字、内容区卖点模块。

## 用户怎么交

指令里写 `模板：` + 文件夹路径（与 `参考库：` 同级写法）。可为总目录（如 `本项目模板`），其下按类分子文件夹（如 `头图品牌框/`）。文件夹内放 PNG 即可，不必自己做 slots.json，不必在指令里标注壳/示意。

## 模板前置（完整制作可含；也可单独执行）

与「参考库前置」同级：指令含 `模板：` 时，须在参考图校验 / 全库参考前置**之前**完成；也可单独只跑本前置（不生图、不跑参考）。失败则**立即停止**并反馈，不进入参考分析或生图。

单独指令见 [提示词模板](prompts.md#单独阶段)。

### 存放位置（对齐参考库 `_参考缓存/`）

默认写在 **`模板：` 路径下的 `_模板缓存/`**（与套系旁 `_参考缓存/` 同习惯），跨项目、跨产品共用；**不要**写进本轮项目的 `输出结果/` 或 `工作文件/` 当唯一源头。枚举模板图时排除 `_模板缓存`（及其中派生文件），不把缓存当壳/示意原件。

典型布局：

```text
本项目模板/                    ← 指令「模板：」指向此处
  头图品牌框/
    头图品牌框.png
    头图品牌框-示意.png
  _模板缓存/
    模板索引.json
    模板前置.md
    头图品牌框.slots.json      ← 需填字时
    slots_满长自检.png         ← 需填字时
```

模板根目录只读或无权写入时：改存本项目 `工作文件/_公共/模板缓存/`，并在索引与报告中写明备用原因（同参考库改存 `公共参考/` 的例外）。

### 复用与失效（学参考库指纹）

复用须同时满足：上述 `_模板缓存/`（或已登记的备用路径）内 `模板索引.json` 与 `模板前置.md` 存在；`status` 为 `passed`；壳（及示意，若有）的 **SHA-256 内容指纹**与登记一致；已锁定 slots 文件可读。任一项变化或指纹不符 → 视为 `stale`，须重跑模板前置，不得沿用旧 slots。指纹未变则**直接复用**，不因新开项目或新跑完整制作而重生成 slots／报告。

本前置输出（**成对**，另在 `project.json` 登记指针）：

1. **机器索引**：`{模板}/_模板缓存/模板索引.json`  
2. **可读报告**：`{模板}/_模板缓存/模板前置.md`  
3. **`project.json` 的 `template`**：摘要 + `cache` / `index` / `report` / `slots` 路径，供本项目后续阶段读取（指向模板旁缓存，不复制一份进输出目录当主存）。

单独跑完须**链接 `模板前置.md`**（并可提索引路径），不能只说写进 project.json，也不能只丢在输出目录。

`模板索引.json` 最少字段示例：

```json
{
  "status": "passed",
  "cache": "本项目模板/_模板缓存",
  "scope": ["main/01"],
  "shell": {"path": "本项目模板/头图品牌框/头图品牌框.png", "sha256": "…"},
  "example": {"path": "本项目模板/头图品牌框/头图品牌框-示意.png", "sha256": "…"},
  "frame_selling_points": true,
  "safe_area": {"top": 0.12, "bottom": 0.16, "left": 0.02, "right": 0.02},
  "slots": "本项目模板/_模板缓存/头图品牌框.slots.json",
  "slots_self_check": "本项目模板/_模板缓存/slots_满长自检.png",
  "brand_on_shell": "好生活 选林草",
  "report": "本项目模板/_模板缓存/模板前置.md",
  "updated_at": "2026-11-18T00:00:00Z"
}
```

`status` 取值：`passed`（可用）、`failed`（本前置未通过）、`stale`（源图或 slots 与指纹不符须重跑）、`missing`（需要模板但尚未跑前置）。报告正文须写明同一状态及失败/过期原因。

校验至少包括：

1. 模板路径可读；递归子文件夹能找到拟用的品牌框类图片（跳过 `_模板缓存`）。  
2. 能确定**可套版的壳**（见下节）；计算并登记壳/示意 SHA-256（可用 `ecom_files.py fingerprint`）。  
3. **壳真透明硬检**（不过则 `status: failed`，停止，不得进参考/生图）：  
   - 用 `ecom_files.py validate-shell <壳.png> --safe-area <top,bottom,left,right>`（默认可 `0.12,0.16,0.02,0.02`）。  
   - 须 `has_actual_transparency`，且安全区内**内容区**近透明像素占比 ≥ `min-clear`（默认 0.80）。  
   - 不达标 → 提示用户提交内容区真 alpha 的壳；索引登记 `shell_alpha: missing`。  
   - **禁止**把项目内临时挖洞/抠芯图写入跨项目 `_模板缓存` 当正式壳；应急派生仅可登记为项目内 `derived_shell` + 原因，且须披露。  
4. 有示意时能看清框上卖点落点（若有）；示意不当最终交付件。  
5. 默认套用范围：**主图01**（头图）；用户另行指定才改。  
6. 若需要框上填字：完成本前置内的 **slots 一次生成与满长自检**；结构先用 `ecom_files.py validate-slots` 检查，再满长套框看图；未通过不得进入后续。  
7. 通过或失败都必须写好**模板旁索引 + 报告**（或已披露的备用路径），并更新 `project.json` 指针（含 `shell_alpha`）；不得只改一处，不得以项目输出目录替代主存。

无 `模板：` 行：跳过本前置，按无模板规则执行。

## 执行者必须做的分析

1. **递归**读取模板文件夹及其子文件夹中的图片。  
2. 文件名可作初筛提示，**仍以看图为准**：  
   - 名含 `原图`：优先当作无卖点壳候选；  
   - 名含 `使用`：优先当作示意候选；  
   - 看图与文件名冲突时，以看图结论为准并登记理由。  
3. 示意常见两种（看图确认）：  
   - **品牌名 + 框**（栏上无卖点字）；  
   - **品牌名 + 框 + 卖点**（栏上有卖点字）。  
   示意若还带完整产品主视觉，仍只作版式参考，**不得当作最终交付成图**。  
4. **壳怎么定**：  
   - 优先用「原图」壳：边框/顶底栏不透明，**内容区须真 alpha**（`validate-shell` 通过）。  
   - 无「原图」时：仅当示意中间内容区已是真透明、且无本品主视觉占满时，可用该示意作壳，仍须过 `validate-shell`。  
   - 全不透明或内容区透明不足 → **校验失败，停止并反馈**；不得靠事后挖洞冒充正式壳。  
5. 常见两态：「原图」+「使用」→ 壳 + 示意；仅一张且可作壳 → 仅壳。  
6. 结合硬表决定卖点落点；默认只套 **主图01**。  
7. 将识别结论写入模板旁 `_模板缓存/` 的 `模板索引.json` + `模板前置.md`，并同步到 `project.json` 的 `template`（含 `cache`/`index`/`report`/`shell_alpha` 与指纹），跨项目共用。

无模板时：不临摹参考品牌框；**不**标「待套版」。

## slots 一次生成与自检（先于分产品制作；缓存跟模板）

需要框上填字时，在**模板校验通过后、多产品生图之前**（亦可在「模板前置」单独阶段完成），由执行者根据壳与示意**只生成一次** slots，并完成自检；通过后写入 **`{模板}/_模板缓存/`**（如 `头图品牌框.slots.json`），**各项目/各产品复用同一份**，不得每个项目再各写一套、事后再回来统一改槽。

生成要求：

1. **先定版式机制**（看示意/Figma，二选一，禁止混用）：  

| 示意/源文件长什么样 | 选用模式 | slots 怎么建 |
|---|---|---|
| 底栏（或顶栏）是**一个文本节点**，卖点与分隔符写在同一串里 | **单行拼句** | 一个槽（如 `sp_line`）；`separators` 为空；登记 `selling_point_compose`；连接符写进文案 |
| 底栏是**多个独立文本框**，中间另有竖线/几何分隔 | **分槽画分隔** | 多槽 + 顶层 `separators` 画分隔；不把连接符塞进各段文案 |

连接符必须**跟示意一致**（全角 `｜` / 半角 `|` / 仅几何竖线），不得混用或擅自改字形。  
2. 对照示意量出槽位 `box`、`align`、`max_chars`（按栏宽与字号估算，宁短勿溢）。单行模式的 `max_chars` = 各段上限与连接符拼满后的整句上限。  
3. 对照示意记录排版（**字号与字重须与示意一致**）：每槽必须写 `font_size`（px，对照示意字形高度估）或 `font_scale`（相对栏高，常见 **0.72–0.85**）；示意加粗/半粗则 `font_weight: "bold"`（框上卖点默认 bold）。  
4. `has_selling_points` 与硬表一致；索引里同步 `selling_point_compose`（若有）。  
5. **自检（未通过不得放行）**：  
   - 结构：`ecom_files.py validate-slots`（可带 `--shell`）；缺 `font_size`/`font_scale` 即失败。  
   - 满长文案：单行模式按 `selling_point_compose` 拼满整句；分槽模式每槽填满。不得只用短句蒙混。  
   - 用壳 + 满长 texts 跑 `composite-frame`，**并排对照示意**看图：满长不溢出；分隔形态与示意一致（拼进字里或旁路画出）；**字号与字重不明显小于/细于示意**；对比可读；不压内容区；**无描边**。  
   - 任一失败 → 调 `max_chars` / `box` / `font_size` / `font_weight` / 模式字段后重检。  
6. 自检通过后锁定 slots，并把壳/示意指纹写入模板索引；后续产品只填各段/各槽文案（服从 `max_chars` 与拼句约定），**不再改 slots 几何、字号/字重、模式与分隔**。模板图指纹变化或用户明确要求时才重做槽位。

### 模式 A：单行拼句（示意/Figma 单文本节点时优先）

```json
{
  "canvas": [1000, 1000],
  "separators": [],
  "selling_point_compose": {
    "slot_id": "sp_line",
    "parts": 3,
    "part_max_chars": 5,
    "joiner": "｜",
    "example": "测测测测测｜测测测测测｜测测测测测"
  },
  "slots": [
    {
      "id": "sp_line",
      "box": [58, 855, 942, 945],
      "align": "center",
      "max_chars": 17,
      "font_size": 52,
      "font_weight": "bold",
      "color": "#FFFFFF"
    }
  ]
}
```

各产品：写 `parts` 段短卖点（各 ≤ `part_max_chars`）→ 用 `joiner` **无空格**拼成一句 → `--texts` 只填 `sp_line`。不要再旁路画分隔。

### 模式 B：分槽画分隔（示意为多文本框 + 独立竖线时）

```json
{
  "canvas": [1000, 1000],
  "separators": [
    {"between": ["sp1", "sp2"], "char": "|", "color": "#FFFFFF"},
    {"between": ["sp2", "sp3"], "char": "|", "color": "#FFFFFF"}
  ],
  "slots": [
    {
      "id": "sp1",
      "box": [120, 858, 340, 942],
      "align": "center",
      "max_chars": 5,
      "font_size": 42,
      "font_weight": "bold",
      "color": "#FFFFFF"
    }
  ]
}
```

各产品：`--texts` 按槽 id 填各段；分隔由 `composite-frame` 按 `separators` 绘制，文案里不要再写连接符。

### 共用字段说明

- **必须**写 `font_size` 或 `font_scale`（对照示意量像素）；禁止两都空靠过小默认。  
- `font_weight`：示意加粗用 `bold`（默认）；仅当示意明显为细体时用 `regular`。Apple 优先**苹方 SC**（粗体 Semibold/Medium），其它系统回退雅黑/Noto；**禁止描边**。  
- `selling_point_compose`：单行模式必填；分槽模式省略。须含 `slot_id`、`parts`、`part_max_chars`、`joiner`。  
- 不得「示意是单行却拆三槽画 `|`」，也不得「示意是分框却硬拼一句」——以示意版式机制为准。

## 卖点放哪里（硬表）

| 参考有卖点 | 模板情况（看图结论） | 做法 |
|---|---|---|
| 无 | 有示意且框上可写卖点（品牌+框+卖点） | 用壳套版；按示意把**本品**卖点写到框上；内容区不放卖点 |
| 无 | 仅壳，或示意仅为品牌+框（无卖点字） | 套壳；内容区不放卖点 |
| 无 | 无模板 | 不临摹参考框；内容区不放卖点 |
| 有 | 有示意且框上可写卖点 | 用壳套版；本品卖点写到框上；内容区不放卖点 |
| 有 | 仅壳，或示意仅为品牌+框 | 套壳；卖点放内容区 |
| 有 | 无模板 | 不临摹参考框；卖点放内容区 |

示意上的字须换成执行卡本品文案。执行卡框上卖点的**字数须服从该槽 `max_chars`**（单行模式还须服从 `part_max_chars` 与拼句后整句上限）；超长先改文案压缩，不把长句硬塞进槽、也不因此每个产品去改 slots。

## 何时套框、何时写框上卖点

默认只处理 **主图01**。壳会压住重叠像素，生图须预留安全区。

| 步骤 | 做什么 | 说明 |
|---|---|---|
| 1. 模板校验 + slots | 定壳/示意；`validate-shell` 过真透明；需要填字则 validate-slots + 满长自检 | 参考/生图之前；壳失败即停 |
| 2. 文案/执行卡 | 按锁定模式写框上卖点；内容区按硬表；`safe_area` 写入生图硬条款 | 各产品只改文案，不改 slots/模式 |
| 3. 生图（内容层） | **一次生成**完整场景：标题与主体落在安全区内；安全区外只放可被框盖住的背景延伸；**禁止**再画店招/色边 | 不让模型画店招框 |
| 4. 审核/返修（已套框看） | 立刻套框再审：融合须「场景完整、框自然压边」；查压栏、色边残留、框上文案 | 返修只改**内容层构图**（标题/主体进安全区）或 texts |
| 5. 返修后 | 改完后**重新套框**再看；通过才交付 | 禁止用整图缩小/留白缩进硬凑当交付 |

### 融合验收（主图01有模板时）

审核对象必须是**已套框图**，不是内容层 alone。

| 合格 | 不合格（不通过） |
|---|---|
| 框压在完整场景上，主体尺度正常 | 整画布等比缩小 + 留白「缩进贴框」后才不压字 |
| 标题/副标/角标短文/主体本来就在安全区内 | 顶栏或底栏切字、压住标题或「地理标志产区」等角标 |
| 压栏时改内容层构图再套框 | 把「缩放硬凑」当正式交付；主体过小、大面积空白塞框 |

**压栏 = 不合格**。典型失败：标题贴顶被绿条/店招条切字；角标与顶栏品牌条重叠。角标短文也须在安全区内。

一轮返修后仍压栏 → 继续改内容层；**明确禁止**「整图缩小塞框」交付。记录压栏大致位置（顶/底/侧）便于返修。

命令：

```text
python scripts/ecom_files.py composite-frame <内容层.png> <壳.png> <输出.png>
python scripts/ecom_files.py composite-frame <内容层.png> <壳.png> <输出.png> --slots <项目锁定slots> --texts <本产品文案.json>
```

### 会不会压内容？

会。防压：生图写安全区；**审核看的是套框后的图**；压住与框上字问题一并返修。

### 「带卖点的框」何时出现？

不单独再生成一张模型画的带卖点框母版。硬表要框上卖点时：锁定 slots（一次，含版式模式）→ 各产品按模式写文案并套框填 texts。硬表要卖点在内容区时：生图写入内容区，套框只叠壳。

无真 alpha 时不做透明底（制作规范第5节）；与品牌框无关。

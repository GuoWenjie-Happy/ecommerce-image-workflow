# 固定提示词结构

本文件是字段模板，不是所有产品共用的固定文案。不照抄占位符；执行者根据实际图片填写，只传该张必要内容，不重复整套流程。每次查看并实际附上所需图片，不能仅传路径文字充当图像输入。

执行卡仍填完整六类商品观察表；compose **默认**打成短「商品核对」进生图串（附图为主）。保真条款原文留在仓库 `product-preservation.txt`，默认不追加；设 `full_legacy_preservation_prompt: true` 可恢复旧形态。实际调用前用prompt_builder.py校验并读取已保存原文和参数，见 [组装说明](prompt-builder.md)。

每次实际调用前展开完整提示词并原文保存到 `工作文件/<产品>/生图提示词/<白底|透明底|主图|详情>/<编号>_初始.md`（返修 `_返修01.md`），将**同一字符串**发送给工具；落盘不存在或为空 → 禁止调用。禁止「同上／见执行卡／摘要」冒充；**主图与详情**营销图／返修均须先 compose 通过（主图不因比例固定 1:1 而免落盘或免 compose）。另记实际附图及调用参数；有离散 aspect 时同记目标档与实际传入档；不把提示词中的目标尺寸冒充独立宽高参数。见 [项目契约](project.md#实际生图提示词留存) 和 [制作规范](workflow.md#实际调用记录)。

发现构图、文案或限制模糊时，回到执行卡的唯一来源修改后重新 compose，不在旧提示词末尾追加局部补丁。上图文字只来自 `copy`/`copy_units`；`internal_notes` 不进提示词；示意页继承产品级 `illustration_system`；有 `layout_regions` 时以区域结构替换自由构图。

## 白底素材

任务：按 amazon-white-background 生成指定SKU、指定视角的产品白底素材。
输入职责：本视角原照为主体；其他照片只核对身份。
产品锁定：真实外形、比例、颜色、可确认Logo/文字、结构、实际配件、不得补造项。
背景构图：纯白、完整居中、主体长边约85%—90%，不拉宽。
输出规格：生成目标为原生2400×2400px，必须保持1:1；工具无法硬控时记录实际尺寸，不伪称达到，也不因实际像素未达到目标单独重出。
限制：保留源模糊，不猜字；不新增文字、道具或水印。

## 透明底素材

编辑目标：已验收的本SKU白底图。仅去背景及必要地面阴影，保持产品与视角，孔洞和半透明边缘正确。输出实际带alpha的PNG，紧凑裁边留少量透明边；设置实际工具的透明背景参数。不能重造另一只产品。

返回后立即按制作规范的正常使用尺度验收并登记状态。自然果皮颜色、高光和实际使用不明显的细边不作为失败理由；明显背景残留、漏抠或轮廓损坏才触发必要返修。未通过须逐张说明位置及实际影响，不等营销图全部完成才补判。

## 参考与文案

先读取所选套系有效逐图分析中的页面购买任务、主体类型、信息组数、标题句式与力度、图文关系、区域和遮挡，以及套系配色、字体、光影和装饰规范；写执行卡和逐图文案时对照本张原参考，并采用缓存中已写清的迁移结构和信息原文，确认任务、模块结构、信息密度和各组要承接的内容；具体迁移提示不能因换气质或场景而丢掉，参考原文须按同样信息位改写成当前商品能成立的内容，不能照搬为商品事实。分析缺失、有歧义、套话过粗、只写结构不写具体内容或难以迁移时回看对应原图并补正，不重复完整分析未变化项。逐图分析须逐项写出该页能读到的信息原文，以及特有标题、印章、信息组类型和构图；只写“有三栏说明”却不写三栏分别说什么，或各页复制同一套构图套话，均不合格。将商品真实事实转为承担相同任务的原创卖点，逐信息位对应，整套通读去重复。先从本品资料提炼有依据的选购因子和调性；每页承接参考的说服任务，主图写短、详情讲清为什么。每个信息位按“事实 → 对购买的意义 → 依据或场景”写成标题加说明，资料只有基本参数时也须展开，不能只写一个标题；氛围或故事页允许稍长的真实场景说明，不编造情节。文案调性须与商品定位和本套定调一致，不能反差过大。内部生成执行卡，准确文案是后续新增文字唯一来源。卖点模块须保持参考的条目数量及“标题＋说明”。参考上的单枚卖点印章或角标须作为信息位承接，不能当装饰省略或只并进主标题。不可用的具体宣称换成承担相同任务的成立内容，不能简化模块、把说明页收成单标题海报、更换页面类型或造证明。用法或加热说明页须保留“怎么用 / 怎么做”的任务；营养成分或参数表须保留表格或同等参数模块，不能改成情景、箱规或合影海报。

原参考基础分析按指纹和规则版本复用。商品分析不锁死风格；选套后结合商品特点、文案主题及参考构图和色彩关系共同策划。执行卡style_basis记录三者依据、气质、配色用途/理由和保留调整项，style写最终方案；页面特有装饰不强加全部图片。同参考多产品分别判断，可合理同色，不复制首个产品方案、不强制换色。适合的配色、光影和装饰可以沿用，仅在与商品、品牌或包装真实冲突时调整。视觉与文案可调整换行、字号、层级和排版，但不能减少信息组、削弱标题力度，不能把说明页或卖点模块收成单标题。设计选色不冒充精确取色；生图明确原参考约束该页任务、模块结构和构图骨架，本产品方案说明如何在此骨架上适配气质、场景和配色。参考里能用的场景只做成同类，必须重新布置环境、道具、光色和机位，不能只换商品而场景几乎不变；画面中有人物时，不能沿用参考里的同一个人或同一群人。白底、参数表、证明页不因此硬加生活场景。使用场合须来自本品资料、定位或该页适合本品的使用关系，不能一遇到场景就写成早餐、午餐、晚餐或一日三餐；一盘鲜果、杯盏等是摆法，不是场合，文案须写出真正的使用场合。首屏、氛围和场景类页面可按方案调整画面气质；说明类页面不得用最终风格改写或删减模块结构。

## 完整设计

输出规格：填写本张唯一目标比例及px宽高（详情按常见七档用 |ln| 选最近；接近时优先更高更竖；上限9:16＝900×1600）。执行卡须写参考宽高比、候选两档、选定档、取舍理由；禁止整套详情默认同一比例；禁止简化成「只用3:4或9:16」。宿主仅有离散 aspect 时：先写目标档像素，再映射最接近传入档，留存同时记两档。期望原生宽约900，能升则升；硬上限未命中不空耗返修，交付须披露原生尺寸与是否上采样。
图像职责：原参考约束本张任务、模块结构和构图骨架；匹配高清素材控制产品；明确商品是否出镜及主视角。跨品类页正向写清场景类型和本品环境。只有实际附加的 `design` 参考图中已存在容易照搬的错误品类、原品牌、证明元素或可识别第三方 IP 时，才按需填 `reference_exclusions`。同类页外壳按 `module_shell` 共享。分级/克重页用纯表呈现；开启 `physical_scale: true` 时写清对齐关系。表格每行提供 `copy_units`。使用场合依本品资料与页面任务具体设定。有品牌框且为本张套用范围（默认主图01）时：写明 `uses_brand_frame` 与 `safe_area`；构图用百分比写出**有效内容宽% / 高%**及四边留白%，标题与主体落在该区内并保持清晰间隔；区外为可被框盖的背景延伸。证明/信任页首轮使用信息卡。
产品锁定：本张适用SKU、结构、颜色、Logo、包装事实与禁变项。
套系规范：本张气质、配色、光影、字体；**只写本张用得上的装饰**，勿把六宫格/斜贴/圆标等整套菜单抄进每页；未授权禁止空装饰类型（云纹/卷草/无依据色块外框等），风格词≠授权加花。字体按 `typeface_policy`（信息字清晰；风格字可创意）。提示词用白话，勿直接写字段名。
区域构图：本张主体、尺度、镜头、标题、信息组、前后遮挡；几窗、道具边界、安全区、同壳、跨品类本品背景用白话写在构图段。章面式单枚辅助卖点徽章的外接直径或最大边≤画布宽20%；普通斜贴、条形角标、功能图标、步骤节点和圆形信息卡按信息层级与可读性确定尺寸。无 `chapter_badge` 不印文件序号圆标。分级默认纯表，构图勿点名尺币。示意页用 `flat_sticker`/`soft_3d_food` 描述。
画面文字：有 `copy_units` 时将其作为画面文字完整集合，逐字呈现；无分位则写本张准确文案。未分配文字的说明区以留白呈现或省略该层。缺包装降级页每模块提供标题和至少一句说明。
内部限制：商品、文案、构图和风格的审核风险写入 `constraints` 和 review，不进默认生图提示词。会进入提示词的字段使用正向目标表达。只有实际 design 参考图里已存在且易照搬的具体元素，才通过 `reference_exclusions` 进入「参考图使用边界」。

## 定向返修

先核实返修历史与授权。**默认**：把执行卡的文案、风格和构图修订为正向最终状态 → compose 完整新提示词 → **重生**（附原参考+高清素材；失败原图只作审核对照）。默认返修提示词不写“移除失败图中的某元素”。仅用户明确要求直接编辑现有图，且文案/结构已正确的极局部问题，才附 `edit_target` 并在 review 写明例外理由。完整使用 poster-style-transfer，一轮内一次模型调用，返回后看图比较，不以最新版自动胜出。

## 简短用户指令

### 无模板（默认）

完整制作：

```text
使用 $ecommerce-image-workflow，完整制作商品主图和详情图。
商品目录：…
范围：全部产品
参考库：…
```

仅主图：`使用 $ecommerce-image-workflow，仅制作商品主图。`

仅详情：`使用 $ecommerce-image-workflow，仅制作商品详情图。`

无模板时不临摹参考店招/品牌框；非品牌框样式仍可参考。卖点按参考有无放入内容区。

### 有模板

完整制作（路径或附图换成实际文件；`模板` 下以后还可追加其它资源）：

```text
使用 $ecommerce-image-workflow，完整制作商品主图和详情图。
商品目录：…
范围：全部产品
参考库：…
模板：…
```

仅主图带模板时，将第一句换成 `仅制作商品主图`，并保留「模板：…」行。

有模板说明（复制上方代码块时不用复制本段）：

1. `模板：` 与 `参考库：` 一样填文件夹；完整制作时先模板前置再参考前置，二者均可单独跑。  
2. 壳须 `validate-shell` 过真透明；需框上填字时按示意选「单行拼句」或「分槽画分隔」，满长自检锁定；各产品只填文案。  
3. 审核看已套框图（融合自然、无缩放硬凑、分隔/字号、无描边、压栏、色边残留）。默认主图01。细则见 [品牌框模板约定](brand-frame-template.md)。

仅详情：`使用 $ecommerce-image-workflow，仅制作商品详情图。`（详情默认不套主图品牌框，除非指令另说明。）

两者均执行所选图片类别的必要上游、制作、审核、必要返修与交付，不制作另一类图片。新项目按上方顺序提供商品目录、范围、参考库，目录名称和位置不限；有模板时再加 `模板：` 段。项目输出默认在商品根目录同级的输出结果，特殊位置才补充项目输出目录。套系缓存始终跟随参考套系。继续或返修已有项目时提供项目总目录，当前上下文可定位时直接写“继续当前项目”；完整重跑新建输出。目录定位和冲突处理见制作规范第2节。

### 单独阶段

以下指令只执行指定阶段，不自动补跑有生成副作用的上游阶段。按需补充商品名、图片类别和编号；阶段输入与停止点见 [项目阶段契约](project.md)。

完整制作若有 `模板：` 先模板前置，再全库参考前置；首次补齐分析，后续仅更新缺失、变化或无效部分，再分派商品任务。模板前置与参考库前置均可单独执行。商品制作中的参考分析用于选套。修改指定文案是按需操作，不是必经阶段。

| 阶段 | 简短指令 |
|---|---|
| 模板前置 | 使用 $ecommerce-image-workflow，仅做模板前置：校验模板并（如需）生成锁定 slots，写入模板旁 `_模板缓存/`，不生图、不跑参考。模板：…。 |
| 参考库前置 | 使用 $ecommerce-image-workflow，仅预分析整个参考库并更新公共选套索引，不生图。参考库：…。 |
| 资料整理 | 使用 $ecommerce-image-workflow，仅整理商品资料，不生图。 |
| 素材处理 | 使用 $ecommerce-image-workflow，仅制作商品白底和透明底素材。 |
| 参考分析 | 使用 $ecommerce-image-workflow，仅分析和选择参考，不生图。 |
| 文案策划 | 使用 $ecommerce-image-workflow，仅策划逐图文案和设计执行卡，不生图。 |
| 图片制作 | 使用 $ecommerce-image-workflow，使用已有执行卡和已验收素材，仅制作商品图片。 |
| 仅审核 | 使用 $ecommerce-image-workflow，仅审核现有图片，不返修、不生图。 |
| 返修 | 使用 $ecommerce-image-workflow，仅返修商品A主图03，要求：…。 |
| 修改文案 | 使用 $ecommerce-image-workflow，仅修改商品B详情02的文案，要求：…，先不生图。 |
| 导出交付 | 使用 $ecommerce-image-workflow，仅导出已通过的图片并制作交付预览，不生图。 |

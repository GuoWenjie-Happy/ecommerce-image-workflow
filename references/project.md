# 项目索引与阶段契约

## 文件定位

目录及路径优先级统一按 [制作规范第2节](workflow.md#2-输入及目录) 执行。商品目录、参考库由用户指定。项目输出与参考套系缓存职责分离；新项目默认使用商品根目录同级的输出结果，非空则新建带时间的目录。只有继续、返修或修改已有图时恢复原记录，完整重跑新建输出，不因发现旧目录自动续做。

产品工作目录只初始化一次并登记project.json；目录名可使用稳定商品名或ID，但全流程复用同一目录。固定子目录为处理素材、生成原件、生图提示词及按需的修复版本，分类树以制作规范第11节为准；图片和提示词不散放产品目录顶层。旧项目恢复沿用既有索引，不按新示例自动迁移。

项目根目录固定保存 `project.json`，项目内容与技能安装目录分离。索引所有项目内文件用相对项目根目录的路径，路径不允许 `..` 逃逸；外部输入首次登记绝对路径，移动或交给别人前把所选商品资料和参考复制进 `输入/` 并更新为相对路径。复制前检查容量与实际可读性，不静默覆盖。共享时明确是否已包含原始输入，不能虚称项目可迁移。

由执行者用文件工具维护JSON，不要求用户手写。先读取现有索引，不按文件修改时间猜最终版；先写新临时文件、验证JSON，再替换索引。并行产品各自写 `工作文件/<产品ID>/product.json`，总控汇总后更新project.json，避免共享写冲突。

最小项目结构如下（示例不是现成完成记录）：

```json
{
  "schema_version": 1,
  "skill_version": "1.0.0",
  "project_name": "项目名称",
  "inputs": {"products": "输入/产品", "references": "输入/参考图"},
  "products": [{"id": "product-01", "name": "商品名", "index": "工作文件/product-01/product.json"}]
}
```

产品索引包含 `facts_file`、`reference_set`、`style_file`、`materials`、`cards`、`images`、`stage_status`、`history`。materials逐项记录SKU、视角、source、white、transparent、检查结论和模糊位置。cards按 `main/03`、`detail/02` 记录参考原图、素材、准确文案、执行卡路径。images同键记录 original、repairs数组、selected、delivered、status、原生/交付尺寸、review、repair_attempts、additional_authorization。路径必须真实存在才登记已完成。history记录时间、用户要求、修改项、版本和额度；删除或移动文件后不可继续声称可用。

### 记录归并与唯一有效版本

归档、JSON更新、计时和总览使用固定 [项目文件工具](../scripts/README.md#项目文件批处理)，清单与payload以文件传递。JSON更新支持按预先读取的SHA-256拒绝过期覆盖；并发产品只写自己的索引，公共写入由总控处理。阶段时间存产品索引 `stage_timings`，环境记录仅在执行环境改变或实际报错时复核。工具未执行完的批次保留成功项，不能把失败写入登记为已完成。

产品 `plan.main/plan.detail` 明确保存应交付编号，未选择的类别用null；不得根据已生成图数倒推计划。每项图片导出成功后记录 `delivered_from` 对应当前selected，自动总览只统计有可读文件且来源一致的通过项。旧索引缺这些字段时先核实，不静默填齐全。

独立产品计划默认记录在宿主计划及product.json的plan、stage_status中，不另存只有通用流程的独立计划.md。本轮已生成的这类文件按制作规范第11节归并独有信息后清理；临时目录按需创建，成功收尾后确认空且无任务依赖再非递归移除。

- 默认保留项目 `project.json`、每产品 `product.json` 和一份当前有效 `执行卡.json`，另按需维护公共参考缓存。产品风格可放在执行卡的公共字段中，`style_file` 与执行卡指向同一文件并注明对应字段，不必为每类内容再拆文件。
- 执行卡style_basis保存商品分析时建立的视觉方向及依据，选套后补充参考保留/调整项和最终配色用途/理由；style为各job的最终风格来源。不得把公共参考配色直接复制为商品方案，字段完整不等于理由成立，仍由AI检查；不为此另建风格记录文件。
- `product.json` 作为状态、选版、素材验收、检查结论和返修历史的唯一有效记录；`执行卡.json` 作为当前准确文案及设计要求的唯一有效记录。索引的 `cards` 可只保存执行卡编号与路径引用，不重复维护另一份文案。修订时原子更新当前执行卡，不默认另存旧执行卡，不建立“历史版本”目录；必要变更摘要与返修额度记录在产品索引，不让 `执行卡`、`执行卡修订` 等多个文件同时充当当前版本。已有旧文件不自动删除，索引只引用当前有效文件。
- 原图检查、白底/透明底检测、数量核对的必要结果直接归入产品索引对应字段。工具原始检测报告仅在排错、审计或工具接口确有需要时保存为附件，并由索引引用；不为同一状态重复创建摘要JSON或复制多份相同报告。不改写已有脚本的输出接口来凑文件数量。既有项目记录不自动删除；本轮临时文件及已归并冗余附件按制作规范第11节收尾整理。
- 白底与透明底分别记录 `status`、所选路径、检查时间和 `review`；透明底未通过时按制作规范记录具体位置、观察条件及实际影响。执行卡登记真实使用的素材路径，不能把未验收素材写成已通过，或用成图通过反推素材通过。
- 透明底review简短记录选版和结论，轻微问题通过并说明；失败只记明显问题的位置及实际影响，不要求额外对比图、显示像素或审核表。返修额度耗尽不作为失败依据。
- 通用字段说明、检查规则和可复用工具归技能维护仓库；商品事实、项目JSON、原图及生成图仍留用户项目，不作为示例提交仓库。公共参考分析也属于用户参考库缓存，不混入技能源文件。

### 实际生图提示词留存

新增任务使用compose组装记录，identity与jobs集中在当前执行卡中，不为每个字段另建JSON。产品索引记录观察表引用及identity/policy/prompt哈希，发送前读取入口核对来源及附图，实际调用仍单独登记。字段规则见 [产品保真组装](prompt-builder.md)。

每次生成或返修前，按 [制作规范第9节](workflow.md#9-第六步逐图完整制作) 保存实际将发送的完整提示词及真实调用参数，之后登记调用状态和返回图片路径。位置统一为 `工作文件/<产品名>/生图提示词/<白底|透明底|主图|详情>/<编号>_初始.md`；必要返修使用 `<编号>_返修01.md`，已发送记录不覆盖。这是图片调用记录，不是旧执行卡备份，不另建一套历史目录或逐图JSON。

产品索引的每项素材或图片登记对应的 `prompt_file`；返修记录登记自己的提示词文件和输出，关联到确切原件。准确文案更新可替换当前执行卡，但不能改写已发送提示词冒充当时输入。旧项目找不到真实调用记录时标记“未留存”，不能从当前执行卡推测并补成已发送内容。

图片附件先通过内容、名称及项目索引匹配；不确定就展示商品、编号及缩略图选项，不要求用户找原参考路径。默认编辑当前选版；多个SKU、同名项目或多个真实候选无法判断时只询问歧义。新索引应从已有文件和可核实记录恢复，不把无记录的返修次数当作0；历史不明时先说明并核实返修额度。

## 公共参考与复用记录

公共参考的保存位置、更新条件及产品风格适配以 [制作规范第6节](workflow.md#6-第三步选择整套参考并建立对应关系) 为准。公共缓存位于参考套系 `_参考缓存/`；不能写入时使用项目 `公共参考/<套系ID>/`。不放入每个产品工作目录，也不计为原参考。

非默认位置必须记录cache_override的具体原因和证据，不能把项目输出目录当作默认缓存位置。迁移已有缓存时核对有效性并更新reference_caches及相关引用，不重做有效分析；正在执行的任务不在外部静默搬动文件。

项目索引可增加 `reference_caches`，登记来源、缓存位置、类别、清单及基础分析规则版本；外部缓存按外部输入登记，项目内路径仍相对项目根目录。产品索引记录使用的清单指纹、基础分析版本以及本产品适配方案路径；`style_file` 指向产品自己的最终风格方案，不能指向公共原配色分析冒充产品方案。已有项目无需批量搬动或删除文件，后续任务先校验可用内容再复用。

分享或移动项目时，只归档实际使用的参考原图及必要分析，每套保存一份并更新各产品引用；明确列出未包含的外部输入。公共缓存是可重建派生物，不等于原参考备份。原参考变化后，不用新缓存覆盖产品曾使用的版本记录；将受影响执行卡和成图标记为待复核，保留旧选版，不自动重做或重置返修额度。

## 阶段输入与输出

| 阶段 | 最小输入 | 输出与停止点 |
|---|---|---|
| 资料整理 | 商品照片和已有产品资料 | 商品事实、SKU与视角归属、证据及缺口记录，不生成 |
| 素材处理 | 商品照片、SKU与视角归属 | 有用视角白底/透明底、检查记录、材料索引 |
| 参考分析 | 商品资料和参考库；无需先生成素材 | 选套理由、逐张对应、比例和风格规范，不生成 |
| 文案策划 | 商品事实、已选参考及风格规范 | 逐图文案和执行卡，不生成 |
| 图片制作 | 所选参考、执行卡、对应已验收素材 | 指定图生成原件；完成轻量检查，按授权返修和交付 |
| 审核返修 | 待审图、原参考、事实、文案及相关素材 | 检查结论；“仅审核”不生成；明确要求返修才执行该阶段修复 |
| 导出交付 | 已选且通过的图片与对应参考编号 | 等比导出、数量核对、两类预览与简短说明，不重设计 |

导出阶段还须按制作规范第11节生成或更新 `交付/交付总览.md`，从现有项目与产品索引及真实交付文件汇总所有产品。根项目索引登记总览路径，不另建汇总JSON；缺失、待更新和未知状态不能遗漏，后续单图返修或重新导出后同步更新该总览。

缺上游先从项目索引和项目目录查找；已有可用内容直接复用。缺失只列具体项，能继续的部分继续；不得为了执行单阶段静默生成上游素材或整套图片。

### 避免重复工作的检查

- 商品事实：原资料和适用SKU未变时复用已核实记录；资料变化只复核相关事实及依赖文案，不能跨商品套用证据。
- 产品素材：来源、SKU、视角和验收要求未变且文件可用时复用已通过白底/透明底，不因新对话重做；失败或未验收素材不能当作缓存通过项。
- 参考数据：按制作规范校验内容指纹，复用尺寸、排序、总览及原参考分析；商品文案、适配方案和成图审核分别执行。
- 工具依赖：当前执行环境已确认可用时直接使用，不重复安装；换解释器、宿主或出现实际故障时重新检查。
- 导出与预览：选版内容、尺寸要求和编号顺序均未变且原输出可用时复用；任一变化只重做受影响输出，不静默覆盖既有文件。
- 读取和校验有效性不等于重复制作；不能为省事省略逐张原参考查看、产品适配或当前成图审核。

文案或风格被修改时，将依赖旧版本的图标为 `needs_update`，保留旧交付，不自动重新生图。用户要求更新图片时只处理受影响项。已用返修额度不因这种标记重置；用户明确要求新设计时另建任务版本并记录授权和原版本关系，不伪装成原任务免费重试。

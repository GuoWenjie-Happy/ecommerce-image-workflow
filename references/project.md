# 项目索引与阶段契约

## 文件定位

项目根目录固定保存 `project.json`，项目内容与技能安装目录分离。索引所有项目内文件用相对项目根目录的路径，路径不允许 `..` 逃逸；外部输入首次登记绝对路径，移动或交给别人前把所选商品资料和参考复制进 `输入/` 并更新为相对路径。复制前检查容量与实际可读性，不静默覆盖。共享时明确是否已包含原始输入，不能虚称项目可迁移。

由执行者用文件工具维护JSON，不要求用户手写。先读取现有索引，不按文件修改时间猜最终版；先写新临时文件、验证JSON，再替换索引。并行产品各自写 `工作文件/<产品ID>/product.json`，总控汇总后更新project.json，避免共享写冲突。

最小项目结构如下（示例不是现成完成记录）：

```json
{
  "schema_version": 1,
  "skill_version": "1.0.0",
  "project_name": "项目名称",
  "inputs": {"products": "输入/产品", "references": "输入/参考图"},
  "products": [{"id": "product-01", "name": "商品名", "index": "工作文件/product-01/product.json"}]
}
```

产品索引包含 `facts_file`、`reference_set`、`style_file`、`materials`、`cards`、`images`、`stage_status`、`history`。materials逐项记录SKU、视角、source、white、transparent、检查结论和模糊位置。cards按 `main/03`、`detail/02` 记录参考原图、素材、准确文案、执行卡路径。images同键记录 original、repairs数组、selected、delivered、status、原生/交付尺寸、review、repair_attempts、additional_authorization。路径必须真实存在才登记已完成。history记录时间、用户要求、修改项、版本和额度；删除或移动文件后不可继续声称可用。

图片附件先通过内容、名称及项目索引匹配；不确定就展示商品、编号及缩略图选项，不要求用户找原参考路径。默认编辑当前选版；多个SKU、同名项目或多个真实候选无法判断时只询问歧义。新索引应从已有文件和可核实记录恢复，不把无记录的返修次数当作0；历史不明时先说明并核实返修额度。

## 阶段输入与输出

| 阶段 | 最小输入 | 输出与停止点 |
|---|---|---|
| 资料整理 | 商品照片和已有产品资料 | 商品事实、SKU与视角归属、证据及缺口记录，不生成 |
| 素材处理 | 商品照片、SKU与视角归属 | 有用视角白底/透明底、检查记录、材料索引 |
| 参考分析 | 商品资料和参考库；无需先生成素材 | 选套理由、逐张对应、比例和风格规范，不生成 |
| 文案策划 | 商品事实、已选参考及风格规范 | 逐图文案和执行卡，不生成 |
| 图片制作 | 所选参考、执行卡、对应已验收素材 | 指定图生成原件；完成轻量检查，按授权返修和交付 |
| 审核返修 | 待审图、原参考、事实、文案及相关素材 | 检查结论；“仅审核”不生成；明确要求返修才执行该阶段修复 |
| 导出交付 | 已选且通过的图片与对应参考编号 | 等比导出、数量核对、两类预览与简短说明，不重设计 |

缺上游先从项目索引和项目目录查找；已有可用内容直接复用。缺失只列具体项，能继续的部分继续；不得为了执行单阶段静默生成上游素材或整套图片。

文案或风格被修改时，将依赖旧版本的图标为 `needs_update`，保留旧交付，不自动重新生图。用户要求更新图片时只处理受影响项。已用返修额度不因这种标记重置；用户明确要求新设计时另建任务版本并记录授权和原版本关系，不伪装成原任务免费重试。

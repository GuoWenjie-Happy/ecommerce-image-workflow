# 电商主图与详情图制作流程

更新日期：2026-11-17。状态：技能包内制作规范；第三方技能保持各自原始文件。

## 1. 目标与优先原则

从商品原始资料开始，为指定产品制作淘宝、京东、拼多多、抖音共用的一套内容。默认不分别设计四套，不自动上传或发布。

- 逐张迁移参考的设计机制，同时保持商品真实、宣传有依据。
- 一张参考对应一张设计母版；主图、详情分别按编号制作，不自动去重、精简、合并、跳过或增加页面。
- 主图目标及交付1000×1000px；详情目标宽900px，按参考选择最近常见比例，候选接近程度差不多时选更高的画幅，目标最高9:16（900×1600px）；逐张写清比例取舍，禁止整套默认同比例。详情实际尺寸比例验收放宽，以完整设计为先。制作不设容量与张数上限，数量严格对应参考。
- 不进行策划确认和首张成图确认，由执行者内部检查后继续。
- 不以空泛文案填版，不以通用照片卡片替代参考迁移。
- 生成原件优先，轻量检查后直接交付；默认不做二次设计、换瓶、贴标签或尺寸后处理。确有明显错误时，由 poster-style-transfer 执行最多一轮必要返修。
- 原参考的品牌、宣称、数据和认证不等于本商品证据；不能为了复刻页面编造事实。

## 2. 输入及目录

目录按以下优先级定位，已能唯一确定的路径不要求用户在提示词重复填写：

1. 用户本轮明确指定的路径和范围优先。商品目录和参考库由用户提供，不固定名称或位置；当前上下文已明确的路径不重复询问，缺失或无法唯一定位时仅询问对应路径，不全盘扫描。输入须真实可读，不能把空目录当有效输入。默认处理全部产品，指定产品或图片类别时按指定范围。
2. 用户说“继续当前项目”、返修或修改已有图时，从当前上下文或用户指定的项目索引恢复原输出位置；无法定位时询问项目总目录。仅发现旧输出文件夹不代表用户要求继续，不自动接管旧项目。
3. 新制作未指定项目输出目录时，使用商品根目录同级的 `输出结果/`。目录已非空则新建同级 `输出结果_YYYYMMDD_HHMMSS/`（重名递增后缀），不静默合并或覆盖旧项目。用户明确要求独立完整重跑时也新建输出文件夹；明确指定的输出位置有内容冲突时只询问该冲突，不擅自覆盖。新输出可按制作授权创建。

路径职责固定：参考库保存原参考和每套 `_参考缓存/`（总览、尺寸指纹、公共AI分析），跨项目复用；模板文件夹保存原模板图和 `_模板缓存/`（模板索引、前置报告、锁定 slots），跨项目复用；项目输出保存本轮 `project.json`、`工作文件/` 和 `交付/`，商品专属执行卡、提示词及成图都在项目内。项目输出目录不接管公共参考缓存或模板缓存，备用缓存条件见第6节与品牌框约定。技能仓库只维护这套相对目录约定，不提交使用者个人绝对路径、项目配置或参考/模板图库。

新对话使用技能入口，只提供本轮输入；已有项目从项目索引恢复。逐图制作提示词仍按第7节自包含。

“完整制作商品主图和详情图”执行全部流程；“仅制作商品主图”或“仅制作商品详情图”限定图片类别，仍执行该类所需的资料、素材、参考、文案、制作、审核、必要返修和交付。仅对所选类别建立参考对应、数量核对和预览，不将未选择的类别列为缺失。明确指定单独阶段时，只执行该阶段。

```text
产品/
  产品A/
    商品图/
    产品资料.md
  产品B/
    商品图/
    产品资料.md
参考图/
  饮品/
    套系01/
      主图/01.png、02.png……
      详情/01.png、02.png……
  水果/
    套系01/
      主图/
      详情/
```

目录分类决定参考用途，数字编号决定顺序。即使主图参考原本来自详情页，放在主图目录中就按主图处理。编号按数值排序。

| amazon-white-background | 第二步直接调用，指导生图工具逐视角制作白底产品素材、锁定身份并检查质量 | 不只读取规则后改用手工描边脚本替代，不执行整套商品图策划 |
| imagegen／实际图片编辑工具 | 以选定白底产品图为输入制作对应透明底，执行必要的视觉处理与局部修复 | 不把白底技能误称为已有透明底流程，不自行重做成另一种产品 |
| 脚本及文件工具 | 检查尺寸、比例、白底、主体占比、alpha及数量；保存归档、命名复制、等比尺寸导出和两类预览 | 不自动接管产品抠图、换瓶、标签重建、构图或风格设计 |

执行前读取实际技能文件。指定的任务边界优先于技能默认流程。技能不可访问或能力不足时如实记录，不假称执行成功。

amazon-white-background固定读取技能根目录 `bundled/ecommerce-image-skills/skills/amazon-white-background/SKILL.md`；它所在的完整集合已内置，附属脚本随原路径保留。集合内ecommerce-listing-suite及其他子技能不自动运行，不接管本流程的策划、确认、后端及返修额度。路径与依赖细节见依赖说明。

技能负责指导制作，生图／图片编辑工具完成视觉，脚本负责检查与文件处理。脚本检查通过只证明对应指标通过，不能替代商品真实性、边缘质量和参考迁移的看图验收。禁止将背景去除、手工轮廓蒙版、原图裁块重建、贴整瓶或标签、边缘拉伸等视觉制作静默切换为临时脚本。工具受阻时说明真实限制，保留已完成结果；不以低质量脚本替代物冒充完成。

### 固定复用脚本

项目记账固定使用技能根目录 `scripts/project_files.py`，说明见 `scripts/README.md`。通过清单文件路径执行批量归档、JSON记录更新、环境记录、阶段计时及交付总览；不把整份JSON或提示词拼入PowerShell/JS命令行，不每轮临时重写这些功能。该工具不生图、不判断保真或代替审核，图片检测、等比导出和预览仍由ecom_files.py负责。

导出交付时优先用project_files.py的一份操作清单串联多张export、批量inspect、明确文件列表的两类preview、count及后续索引/overview操作；图片处理内部复用ecom_files.py，不另写外层PowerShell循环逐张发命令。全部输入须为已核实选版，不通过任务不得混入。每项保留结果，失败停止后续依赖操作，核对后只恢复失败和未执行项，不盲目覆盖或重跑已完成导出。

技能根目录的 `scripts/ecom_files.py` 是固定文件处理入口，说明见技能根目录 `scripts/README.md`，依赖见 `scripts/requirements.txt`。每轮直接复用，不重新编写素材处理、导出或预览脚本，不在各产品目录复制修改一份。使用实际可运行的Python，不假设系统python别名可用；依赖已安装则不重复安装。

| 子命令 | 用途 |
|---|---|
| inspect | 检查文件解码、实际像素与比例、alpha、近白边缘及近似主体占比，可写JSON记录 |
| export | 仅等比导出；主图用 `--width 1000 --square`，详情用 `--width 900`；标记上采样 |
| preview main | 从通过主图目录制作按编号排列的完整画面联系表 |
| preview detail | 从通过详情目录制作按编号等宽、从上到下连接的纵向预览 |
| count | 按相同编号文件名核对参考与交付，报告缺号、多号及重复编号 |

脚本拒绝覆盖既有输出，返修或重导出使用新文件名；不会修改输入图片。预览输出放在主图／详情目录之外，避免混入编号和数量检查。原图及生成返回文件的原样复制、命名、归档可使用系统文件操作，不需每轮造新脚本。缺少通用功能时再维护本目录，不能因此扩大到视觉制作。指标检查是辅助证据，不代表包装、风格或合规审核通过。

## 4. 第一步：商品识别与资料整理

### 集中启动与定向追加

本轮开始集中读取阶段所需规则、项目索引和本产品索引，核对可访问输入、输出权限、已有解释器/依赖及宿主图片能力，登记检查结果。已有当前宿主的有效解释器记录时先直接验证该路径，不重新全盘找Python；环境未变且已确认可用的检查不反复执行，不重复安装。环境记录只证明当时检查项，工具报错、切换解释器/宿主或依赖变动时重新核验受影响部分。

追加指定图片时，从索引直接定位当前选版、原参考、高清素材、执行卡、实际提示词及历史返修额度，一次读取相关上下文；不重新扫描全部产品、重新选套或整理无关文案。缺失字段按所选阶段补齐，歧义只处理该阻断项。用户明确要求从头重跑时另按其范围执行，不能借效率复用用户要求重做的成果。

阶段开始/结束用project_files.py计时操作写入产品索引，同一产品内使用“启动-第1轮”“素材-第1轮”“生成-第1轮”“审核-第1轮”“返修-第1轮”“交付-第1轮”等唯一ID。没有独立耗时证据的间隙不能伪拆成模型耗时；并发阶段记实际时间区间，不把重叠秒数相加。生图记录继续关联真实调用和返回，不额外为每个检查再建计时JSON。

### 多产品分派节点

完整制作的启动顺序为：总控检查输入和环境→**若指令含 `模板：`，先执行模板前置（校验壳/示意；需填字则一次生成 slots，并按各槽 `max_chars` 满长出字套框自检；失败则停）；模板前置也可单独执行，见品牌框约定**→完成全库参考前置（亦可单独执行）→轻量清点独立产品、SKU归属及各自输入目录→随即创建每产品子任务/子计划→各产品开始详细资料分析和商品观察表。不要先由总控完成全部产品的详细分析或素材制作后才分派。清点中的归属歧义只澄清对应项，不阻断可确定产品。无 `模板：` 时跳过模板前置。各产品复用已锁定 slots，只替换本产品框上文案；不得每产品重做槽位。

每个产品任务从下方商品资料分析开始，独立走完观察表、白底/透明底、参考选套、逐图策划、制作、审核返修和交付。总控负责公共参考缓存与索引的检查及必要更新，产品任务只读复用，不各自重跑全库；最后统一生成交付总览。子任务获得本产品输入路径、独立输出目录、所选范围、规则入口和公共索引位置，不复制其他产品资料。

独立子任务/子计划是任务分派要求，不要求额外生成“独立计划.md”。默认以宿主计划及产品索引的plan、stage_status记录范围和进度，不把通用流程再抄成单独文件。本轮已生成的独立计划若仅有通用步骤，收尾时归为冗余文件清理；若有独有的产品决策、待办或恢复信息，先归入产品索引，核对后再清理。不能为了目录整洁丢失任务状态。

1. 只读取指定目录，识别独立产品及SKU关系，列出处理清单。文件清点用project_files.py的inventory集中采集，AI据清单查看相关原图和资料；相同内容只作提示，不自动推断SKU或删除照片。
2. 每个产品独立建立事实与素材记录，不混用照片、参数、品牌、包装、文案。
3. 核对名称、外形、规格、实际包含物、包装与证据；模糊文字不猜测，明显冲突单列核对。
   商品资料与照片冲突时，以照片中可确认的实际商品、包装及可读标签为准；无法判断的字段省略或列为缺口，不停住整套流程。不能仅凭照片猜测产地、材质、功效或销售件数。
4. 未提供证明视为没有，不反复索要；不得编造产地、工艺、口感、功效、销量、认证、促销等。
5. 商品名称缺失时可按授权拟通用品类工作名；无法识别品类或素材归属时，只询问该阻断项。

为每产品/适用SKU建立identity商品观察表，包含外形比例、结构、颜色材质、图案、全部文字区域及附件六类；按实际证据填写可见/不可见/不适用及原因，不只摘品牌、品名、容量。观察表留在执行卡供全程核对；**默认生图提示词**组装为短「商品核对」+一遍硬要求（附图为主），不把英文字段整表和保真条款全文塞进生图串。保真原文仍归档在 `references/product-preservation.txt`；若要恢复旧形态，compose 设 `full_legacy_preservation_prompt: true`。详见references/prompt-builder.md。脚本不替代观察准确性核对。

商品分析阶段记录包装视觉、颜色材质、实际用途、购买动机、用户要求及有依据的品牌/价格定位，作为后续风格判断的商品依据；此时不提前锁死配色、字体、光影或装饰。选定参考后，在逐图文案策划中结合商品特点、内容主题、参考构图和色彩关系共同确定最终视觉方案。包装色不等于背景必须同色；未知定位不凭空写成高端、年轻或健康等事实，审美判断明确为设计选择。依据及理由集中放当前执行卡style_basis，不另拆风格JSON；设计选定色号不冒充测量取色。

一产品一独立执行计划／子任务，各自完整负责资料、素材、参考、创意文案、制作、审查、返修和交付；在宿主具备子代理能力时，分配独立子代理并行推进各产品，不由一个执行者在同一上下文中从上到下交错操作所有产品。总控负责公共规则、产品分派、服务并发限制和最终汇总，不代替各产品反复重策划。共享规则只读，各产品只写自己的目录，不互相覆盖素材和计划。产品内可并行独立图片任务，有素材依赖时先等待该素材验收。

宿主不具备子代理能力时保留独立计划和资料隔离，可顺序执行，并如实说明未实现并行，不把一份勾选清单称为多个独立执行者。不自动创建用户侧新对话。一个产品受阻不阻断其他产品，不要求中途确认。商品资料不足不等于可以用废话填满对应页面。

## 5. 第二步：制作高清白底图与透明底素材

本步为正式制作步骤，不得仅写预处理规范后跳过，也不再视为可省略的“按需处理”。商品识别与资料整理完成后，先为每个产品建立可用产品素材，再进入参考与成品制作。

### 原图内容分类与未知处理

主体由实际销售事实决定，不按画面面积、居中位置或视觉显眼程度判断。先使用用户明确说明，再核对产品资料、SKU及销售规格、包装或箱标，最后用多张原图的稳定对应关系辅助判断；单张照片只能证明画面中存在该内容，不能单独证明它随商品销售。不要用笼统的“主体／辅助”二分法跳过证据核对，逐项归入下列类别：

| 类别 | 判断含义 | 素材处理 |
|---|---|---|
| 销售主体 | 用户实际购买的核心商品 | 保留并建立所需视角素材 |
| 销售包装 | 实际交付的箱、盒、袋或瓶；与内容物共同构成销售单元 | 保留包装视角，核对包装文字和结构 |
| 内容物 | 包装内实际销售的水果、食品或其他商品内容 | 按页面需要建立整体或局部素材 |
| 随货配件 | 有资料或多视角证据确认随商品交付的附件 | 记录归属后保留，不与道具混用 |
| 拍摄道具 | 仅用于摆拍、承托、切割、饮用或尺度展示的物品 | 干净商品素材中移除，场景策划可参考 |
| 人物或手部 | 拿取、展示或使用关系 | 干净商品素材中移除，需要场景时重新按证据设计 |
| 环境背景 | 桌面、果园、仓库、墙面等拍摄环境 | 白底和透明底素材中移除 |
| 未知内容 | 现有证据不足以判断是否属于销售单元 | 保留原图证据，进入下述未知闭环，不先删也不先保留为商品 |

同一销售单元可以有多个主体层级。例如销售“一箱苹果”时，苹果是内容物，箱子是销售包装，二者共同构成商品主体；销售散装苹果时，普通运输箱只有在资料或其他证据确认不随货后才归为拍摄或物流道具。包装里外、封箱、开箱和单果视角可以分别建素材任务，不要求一张素材同时表达全部层级。

未知不等于辅助内容，也不等于必须永久保留在成品中。发现未知内容时：

1. 在产品索引记录未知对象、所在原图及位置、已检查证据和缺少的判断依据。
2. 优先检查用户说明、产品资料、销售规格、箱标／包装文字及其他视角；有足够证据后改归明确类别。
3. 仍无法确认时保留原图，不擅自删除、补造、写成随货内容或据此创作文案；含该未知对象的结果不得进入已验收的白底或透明底素材。
4. 有不含未知对象且能确认商品完整的其他视角时，先使用该视角继续；没有替代视角时，只阻断依赖该判断的视角或任务，不阻断其他产品、其他已确认素材和无需该内容的页面。
5. 在素材缺项或交付限制中说明实际影响。用户补充证据后更新分类和受影响任务，不要求无关阶段重做。

1. 全部商品原图均须查看和归档用途，不只看第一张。按SKU及正面、侧面、背面、细节、标签、配件、使用场景分类；清楚区域交叉核对。所有有用且不同的产品视角分别准备对应白底和透明底素材，重复照片不重复处理；标签、内容物及场景照片用于相应核对或素材任务，不机械地全部抠成整瓶。后续每张成品选择最匹配的素材，不无差别附上全部图片，也不全套只认主视角。
   内部先列“原图→保留视角→白底文件→透明底文件”清单，逐个视角建立独立制作任务。不把多张不同视角照片全部合入一次调用、只生成一个产品视角；其他照片可以辅助身份核对，但每次须指定本次主要视角。核对计划视角数与实际两类素材数，缺项说明原因，不以商品数量代替视角数量。
2. 直接调用 amazon-white-background，以该视角原照片为主要输入、其他相关照片辅助核对，使用生图工具生成完整干净的白底产品图；清除原背景、手部和非售卖道具，保持可确认的真实商品外形、颜色、Logo及包装。手持关系可用于后续场景设计，不等于一律禁用手部。不得误删真实结构，不把可见附件自动认定为随货配件，用户明确排除的内容优先执行。
3. 查看白底生成原件，核对产品、标签、轮廓、孔洞、光影与完整性，再选用素材。生成结果整体好而只有局部问题时，用图片编辑工具定向处理，不因小字问题自动退回手工描轮廓脚本。不得默认认为“原照片像素版”或“最新处理版”更好。原图遮挡无法确定的结构不补造；仍有明显错误的素材不能冒充通过。
4. 以选定并验收的白底产品图为编辑输入，使用 imagegen／实际图片编辑工具去除白色背景及需要移除的地面阴影，制作对应透明底PNG。宿主若不能输出真实alpha透明底，则本步不做透明底，在素材索引登记能力不足；不得用近白底、去底近似或棋盘格预览冒充透明底并继续依赖透明底的下游。有能力时尽量保持产品像素和视觉不变，检查实际alpha、孔洞与半透明边缘。白底和透明底必须同SKU、同视角、同产品，不从原照片另行脚本重建第二种外形；去背景引入变化则定向纠正或记录未通过。依赖透明底的合成任务在透明底缺失时标阻断，或改用该页允许的不依赖透明底做法，不得静默顶替。
5. 白底生成目标为原生2400×2400px，原件必须保持1:1；产品完整、居中，主体包围框长边占画布边长约85%—90%，避免大白底、小产品。细长产品不得横向拉宽以追求面积占比；阴影和外发光不计入主体。实际像素尺寸不是2400×2400px不作为返修或重出理由，仍须记录原生尺寸与宿主能力上限；非1:1、商品或包装错误、明显背景问题及构图问题仍按实际缺陷处理。透明底紧凑裁边并留少量透明边。

   白底交付尺寸固定为1000×1000px：通过验收的正方形原件使用 `ecom_files.py export --width 1000 --square` 等比导出，大于1000时缩小，小于1000时允许放大并标记上采样。放大不能恢复真实细节，不得把交付尺寸称为原生高清。后续根据实际清晰度选择已验收的紧凑白底或透明底产品输入。
6. 白底制作必须实际执行 amazon-white-background 的生图路线，而非只采用其检查规则。可以读取 ecommerce-listing-suite 的白底调用节点作为路由，但不必额外运行该总控，也不执行其套图策划。素材使用本文的主体占比及交付规则，不把白底素材处理误当成四平台成品上架审核。
7. 清晰度优化只做不改变商品事实的处理；禁止靠生成补字、重画Logo或虚构纹理实现所谓高清。源素材模糊时保留可确认内容，记录真实分辨率及限制，不要求产品凭空变清楚。
8. 对照原图逐项检查外形、比例、颜色、Logo、包装文字、边缘、透明孔洞和实际配件；检查白底纯度及透明底alpha。正常使用时明显可见的背景残留、漏抠孔洞、非商品手部带入或轮廓损坏属于处理问题，不能以“原图固有模糊”放行。透明边缘按下述实际使用标准判断，不能仅凭绿色或黄色判错。生成新增的实质错误须修复，原图固有模糊按第10节规则处理。脚本只能检测和记录，不通过自动改色、描蒙版或拉边来伪装修好。

### 素材即时验收与透明底标准

- 白底和透明底生成后立即验收，分别登记状态，不等成图结束才补检查。
- 透明底以正常使用时整体自然、商品正确、背景真实透明为通过标准。允许少量杂点、细线、轻微毛边和不影响使用的局部残留；不追求完美抠图，不因放大才看到的小瑕疵返修或扣留。
- 只有商品明显变形、缺失部件、大块背景未去除或正常查看就明显影响使用时才未通过，简短注明位置和影响即可。不强制制作浅深背景对比、计算显示像素或填写额外审核表；有疑问时再辅助查看。
- 必要返修后选实际更好的一版；初版可用就交初版，不因返修未解决细小问题或额度耗尽而判失败。轻微问题通过并简述，不增加返修次数。
- 下游只用已通过的实际素材，白底与透明底状态独立；某类未通过只阻断确实依赖它的任务，不反推其他已通过图片失败。

每个产品至少有主视角白底版和透明底版，不能以此最低要求代替其他有用视角的处理。白底与透明底使用相同SKU及视角编号，执行卡可追踪回原图。原图已经符合要求时可复用，但仍须验证并保存对应文件。遮挡导致无法真实提取完整商品等实际阻断须说明，不补造结构，也不假称完成本步。

本步不设置额外人工确认。通过后，白底与透明底作为下游保真素材使用；不强制每张成品贴同一视角，不以白底图替代完整参考迁移。

文件保存：工作文件/产品名称/处理素材/高清白底、透明底。另在最终交付目录的“产品素材”中提供通过检查的两类素材；仅因原图固有模糊通过的素材，也须在交付说明列出文件名及模糊位置。

具体顺序固定为：视角清单→读取并调用 amazon-white-background→生图工具返回白底原件立即保存→用 `ecom_files.py inspect` 读取尺寸、比例、近白边缘和近似主体占比并结合看图检查→必要定向处理→选定白底产品→图片编辑工具制作同视角透明底→对应检查→白底等比导出1000×1000px并归档。脚本不得承担产品重建或去背景。使用内置图片能力，不因技能列有模型名或第三方入口就切换收费API，也不能在模型身份未返回时声称使用了技能列出的指定模型。

### 下游必须使用已验收高清素材

后续逐图制作必须使用第二步已验收的高清白底或透明底产品图作为产品输入，按SKU、视角和局部匹配，不得完成预处理后将这些素材闲置，又只用未处理原照重新生成产品。执行卡记录本张使用的高清素材文件及用途。

- 整体场景生成：使用匹配的高清白底产品图作为商品保真参考，原参考图控制该页任务和构图骨架，不得原样搬用参考场景、只把商品换掉。
- 产品合成：使用匹配的透明底PNG作为产品层，保证真实轮廓和标签。
- 标签或局部修复：优先从已验收高清素材取对应区域。
- 原始照片保留作真实性、颜色及细节核对；已处理素材未覆盖的视角，回第二步补做并验收，再用于后续制作。
- 明确不需要产品出镜的辅助图案页可不传产品素材，不强行放商品。禁止为满足素材使用要求而全套重复一个视角。

## 6. 第三步：选择整套参考并建立对应关系

### 模板前置（有 `模板：` 时先于参考；也可单独执行）

当用户提供模板文件夹时，总控按 [品牌框模板约定](brand-frame-template.md) 执行模板前置：递归识别壳与示意（跳过 `_模板缓存`）、默认套用主图01、量安全区并登记 **SHA-256 指纹**；壳须过 `validate-shell`（内容区真 alpha）；需要框上填字则一次生成 slots（先 `validate-slots` 再满长套框自检），通过后锁定。结论必须成对写入 **`{模板}/_模板缓存/`** 的 `模板索引.json` 与 `模板前置.md`（及 slots／自检图；状态 passed/failed/stale/missing），`project.json` 的 `template` 登记指针与 `shell_alpha`。模板目录不可写时改存项目 `工作文件/_公共/模板缓存/` 并披露。单独执行结束时回复须链接报告。本前置不生商品图、不跑参考库分析。壳无真透明或其它失败同样写索引+报告后停止，不得挖洞冒充正式壳。指纹未变则复用；源图变化则标 stale 并重跑。

### 参考库前置分析（完整制作中在模板前置之后；也可单独执行）

完整制作在（如有）模板前置通过后执行全库参考前置：检查用户指定参考库的全部套系，首次补齐逐图分析和套系摘要，之后只分析新增、修改或无效部分，刷新根目录公共选套索引，再启动商品任务。不是每轮重新分析全部图片，也不能只检查所需候选就宣称完成全库前置。此公共阶段由总控统一负责，各产品不重复执行。有坏图或不可读套系时如实标明未完成项和范围，继续可处理部分；不可用部分不得标为已分析或索引完整。也可不带商品制作、单独只跑本前置。

“仅整理/预分析整个参考库”也可独立执行本节，完成后停止，不分析商品、不生商品图。先枚举用户指定参考库中的全部实际套系，排除_参考缓存、_公共参考及已登记派生目录，建立含类别目录的完整套系清单。首次逐张查看全部原参考并分析，后续由指纹检查仅更新变化图片及受影响公共结论。完整制作主图与详情时覆盖两类；仅制作主图或仅制作详情时，检查全库各套系中所选类别，不扩成另一类商品制作。

每套在 `_参考缓存/main_analysis.json`、`detail_analysis.json` 保存独立逐图分析和套系摘要，结构见scripts/README.md。逐图明确原图具体内容，并逐项记录能读到的信息原文：主副标题、每个卖点的标题和说明、卖点印章或角标短句、表格行名和关键数值、其他辅助文案；看不清的标明不可读。同时记录信息组类型和数量（几栏、几格、标签组还是表格）、图像内容、购买任务、表达力度及依据、图文位置与对应关系、该页特有的构图层级和遮挡、可迁移机制及不可照搬的原商品事实、不确定项。只写“有三栏说明”却不写三栏分别说什么，不算合格。这些是参考原文，供执行卡按同样信息位改写成当前商品能成立的内容，不能当成当前商品事实照搬。构图和迁移说明必须能区分这一页，不能各页复制“商品居中、标题在上”这类套话。每条绑定类别、路径、SHA-256和从1开始的顺序，不能只写“卖点页/场景页”。套系摘要描述形态适配、设计特点、模块组成、所需素材、可调整项及共同风格，不将原参考宣传作为当前商品事实。

AI对照原图抽查逐图记录与摘要的一致性，覆盖具体信息原文、表达力度、图文关系、信息组类型和数量、特有构图及不确定项。只写结构不写各组实际内容，或各组内容与原图不符，视为不合格。若多页构图或迁移说明可以互换而不损失信息，视为套话、不合格。以上情况须对照原图补正后再登记检查通过。脚本只核对字段、绑定、顺序和检查声明，不证明观察正确。新增、删除、改名、内容或规则变化后，更新分析及受影响摘要，分析未完成不只改指纹冒充有效。

用 `scripts/reference_catalog.py` 依据套系清单批量刷新缓存，并从有效套系分析汇总根目录 `_公共参考/选套索引.json` 和 `选套说明.md`。详细分析只在各套系维护，公共索引派生生成；missing、stale、incomplete套系继续列出并注明状态，不静默丢弃。清单漏套系或扫描失败时必须披露，不把旧索引当当前全库结果。库不可写时按真实权限限制明确说明，不把根目录索引静默改放项目中。

商品制作先分析商品事实、特点与购买动机，再读公共索引筛选候选、读候选详细分析选套；选套不以预先锁定的配色为筛选条件，优先判断构图、页面任务及表达机制的适配性。有效且完整的逐图分析是选套和策划的默认输入，不因复用缓存而跳过对照原图，也不等于每轮重做全库分析。写执行卡和逐图文案时，必须同时对照所选套系对应原参考，以及缓存中已经写清的迁移结构和信息原文；确认该页任务、模块结构、信息密度和各组要承接的内容。缓存里写明的具体迁移提示必须采用，不能因为更换气质或场景而丢掉；参考原文按同样信息位改写成当前商品能成立的内容，不能照搬为当前商品事实。缓存描述缺失、歧义、套话过粗或难以承接时，回看原图并补正公共分析。看原图不等于重做分析。实际生图仍附本张原参考，审核仍对照原参考；各产品分别协调文案和最终风格。缓存的结构有效不等于内容可靠；前置流程尚需真实商品对照测试确认质量和效率，不承诺成图效果持平。

### 公共参考准备与更新检查

客观参考准备固定调用技能根目录 `scripts/reference_cache.py`，用清单一次传所需套系和main/detail目录，采集编号、尺寸、比例、指纹及分类总览；不再临时写脚本逐张处理。按updated与analysis_required决定复用或更新，缓存授权与回退位置在清单明确指定。缺图、坏图、重复编号必须如实处理；详见scripts/README.md。

- 公共缓存默认放在每个参考套系的 `_参考缓存/`，保存主图/详情总览、原参考基础分析及文件清单；同一套参考跨产品、跨项目共用，不在每个产品目录重新拼图或复制一份。只写派生缓存，不修改参考原图；参考库只读或写入未授权时，改存本项目 `公共参考/<套系ID>/`。套系ID须区分不同来源的同名套系，并在清单中登记来源。
- 用户提供参考库并要求制作时，按默认规则准备派生缓存；不能仅因另有项目输出目录就推断参考库不可写。正常清单省略cache。只有实际写入失败、明确的权限限制或用户明确指定其他位置时，才设置非默认cache，并提供cache_override的kind和具体evidence，向用户说明原因和实际路径；字段见scripts/README.md。脚本拒绝缺少原因的覆盖，不另写临时命令绕过。既有项目缓存先核对来源、原图指纹、分析规则和文件可读性；需迁回默认位置时复用有效内容、更新项目引用，不为迁移重新生图或重分析，不自动覆盖冲突缓存、删除旧目录或干扰正在执行的任务。
- `_参考缓存/`、根目录 `_公共参考/`、项目备用 `公共参考/` 和其他派生文件不作为原参考枚举或计数。只做详情时仅准备详情缓存，只做主图时仅准备主图缓存；全库前置覆盖指定参考库各套系的所选类别，商品选套阶段再按需比较候选。总览辅助选套；有效详细分析可供策划复用，总览不能作为生图参考输入。
- 首次记录原参考的相对路径、类别、数字顺序、实际尺寸与SHA-256内容指纹，以及基础分析规则版本。每次使用先枚举并核对所需类别的文件清单和内容指纹，不只依赖文件名或修改时间。发现新增、删除、改名、顺序或内容变化，只更新受影响类别的总览和相关分析；规则版本变化只更新受影响分析，不无故重拼总览。没有变化且缓存文件真实可用时直接复用。缓存缺失、损坏或版本不明时按需重建，不假称命中。
- 公共基础分析只描述原参考的页面角色、构图、信息层级、字体、原配色、光影和装饰机制，不包含当前商品的事实、文案或最终风格。原参考的证据和宣传内容不能作为商品事实缓存复用。
- 根据缓存工具的analysis_scope执行：none复用；incremental按analysis_changes逐张补充、移除或修订分析，不因再次扫描无变化而漏掉尚未完成的分析任务。AI再判断变化是否影响共同配色、字体、光影或页面顺序，只复核受影响的公共结论。例如新增一张规格页通常只补该页；替换定义整套风格的首屏可能需要复核整套风格结论，不等于重做所有逐图分析。full表示首次或有效分析依据/规则不可复用，重新建立该类分析。更新完成后以当前指纹和规则版本保存完整有效分析，不能只更新指纹或把脚本变化清单当成AI分析。
- 参考提供页面任务、信息层级、模块结构、构图机制及可借鉴的色彩与装饰关系，不提供可照搬的品牌、标识、原品名或原商品宣称。商品提供身份、特点、调性、用途及购买动机。两者结合本商品文案主题共同决定视觉方案：适合的配色、字体、光影和装饰可以沿用，仅在与商品、品牌或包装真实冲突时调整并记录理由；不能预先锁死商品配色再硬套参考，也不能把参考当成可以忽略结构的氛围图。同一参考用于多个产品时，每产品分别判断具体颜色、明暗、用色比例、字体气质和光影，记录沿用或调整的理由；不把首个产品的style复制给其他产品。同品牌系列或确实适合时可同色，不强制为不同而换色，同产品整套保持协调，各张保留原参考自己的页面任务和模块结构。
- 产品目录只记录选定参考原图、公共分析版本和本产品适配方案。生图时同时提供原参考与本产品方案。原参考约束该页任务、模块结构和构图骨架；本产品方案说明如何在此骨架上适配商品气质、场景和配色，场景只可做成同类，不能原样搬用参考环境并只换商品，人物也不能是参考里的同一个人或同一群人。首屏、氛围和场景类页面可按方案调整画面气质，但须保留该页关键信息；说明类页面不得用最终风格改写或删减模块结构。不能只传缓存摘要。公共缓存由总控集中更新，产品任务只读；更新先写临时文件，验证完成后替换，避免并行覆盖。

### 产品选套与逐张对应

1. 优先从公共索引查看产品所属分类的候选，再读取候选套系详细分析；没有适合项才比较相近分类。摘要仅筛选，不能仅凭简短标签排除可能适合的套系。未分析、过期或不完整候选按需补分析，不当作不适合。
2. 根据商品形态、购买理由、主要模块可迁移程度、现有资料和素材、品牌调性选择一整套，不仅看颜色或同品类。优先比较设计适配性，再用本商品内容承接；不能因缺原参考同款产地、检测或糖度证明而降级选套。不能照搬的证明图形单独处理，不照搬认证和检测背书外观。
3. 默认不跨套混搭。说明选套理由后直接继续，不增加人工确认。
4. 不以参考中原产地、检测、糖度、工艺或认证无法照搬为由，直接判断整套参考不可用。先判断能否保留构图与表达机制，用本商品有依据的卖点、使用场景和情绪表达逐张重写。只有实际没有可迁移的设计、商品身份不清或缺少必要视觉素材等真实阻断，才标记参考不足，并明确具体原因；不能因缺原参考同款证明就停止整个产品，也不能强做通用模板。
5. 每张参考建立对应记录：原文件、原尺寸、原比例、成品编号、页面角色、主要区域及替换方式。有效详细分析复用，缺失或有歧义时回看对应原图；编号与顺序来自实际文件清单，不从摘要猜测。

选定套系后，主图参考N张就做N张主图母版，详情参考M张就做M张详情母版。重复参考也不自动去重。必要内容冲突如实列为该张待解决项，不静默少做。

## 7. 第四步：逐图卖点与设计执行卡

### 7.1 先理解参考为什么能卖

每张读取有效详细分析中的购买理由、证据方式、标题句式与力度、各组信息原文、辅助说明、画面如何支撑卖点，以及已写清的迁移结构，并对照本张原参考确认模块结构、信息密度和各组要承接的内容。缓存中的具体迁移提示必须采用，不能只改风格或场景就换掉结构；参考原文按同样信息位改写成当前商品能成立的内容，不能照搬为当前商品事实。分析缺失、过粗、只写结构不写具体内容或无法承接时，回看对应原图并补正，不重复完整分析未变化项。

每个产品先从本品资料提炼有依据的选购因子、核心购买动机、差异点、表达主题和文案调性，不从其他产品复制“日常／一日三餐”等通用方向，也不把这件商品的场景页默认写成早餐、午餐、晚餐。产品间可以共享工具和检查规则，不能共享同一套宣传概念。根据本商品资料及所选参考决定强调口感、原料、产地、规格、使用便利、外观质感或其他有依据的价值；信息不足时不编造差异。

再根据本商品事实，写出承担类似购买任务的原创内容。因本流程逐张对应参考，不改页序；每页文案方向承接参考这页的说服任务，用本品选购因子里能成立的内容填写，不能把整套都收到两三个同一口号上。主图负责让人看清“这是什么”和最值得记住的一点，文案短、一图一事、偏记忆点；详情负责把为什么买、凭什么相信、怎么用或规格是什么讲清楚。具体程度跟该页任务走，不能用主图的短法写详情，也不把首图或氛围主图写成详情长文。

每个信息位按“事实 → 对购买的意义 → 依据或场景”来写：标题管记忆点，说明讲清理由。资料只有产地、配料、规格、工艺等基本参数时，也须把参数展开成标题加说明，不能只推导出一个短标题。例如仅有“无糖配方”，应写明配料不含蔗糖及这对日常饮用意味着什么。不能从参数编造资料未写的古法、次数、功效、人物经历或传说。某一信息位本品参数实在撑不起参考原任务时，改用另一项能成立的参数写完整说明并记录原因，仍须有说明，不能只剩标题。

#### 密文页文案完整性硬闸（生图前）

参考该页凡属「标题＋说明」的信息位（双列对照表每格、卖点多栏、四宫格及以上每格有正文、多行表等），执行卡必须写出**同等数量、可直接上图的完整标题与说明**，不得只枚举短标签。

- **密文页**：双列对照、多行表、四宫格及以上且每格有正文、参数表等，信息密度高、说明区大。此类必须设 `dense_copy: true`，并提供 `copy_units`（每项含非空 `title` 与 `body`；仅短印章位可 `title_only: true`）。  
- **硬闸**：任一须有说明的信息位缺 `body`、或只有短标题列表 → **不得 compose、不得调用生图**；阻断并补文案。禁止「版式按参考留出大段说明区、文案却只给标题、交给模型填」。  
- **表格行硬闸**：`layout` 要求表格/分级表时，**每一行**须有列对齐的 `copy_units`（title/body）；禁止本页画表壳却写「见另一页分级表」留空行。参数页若只需键值列表、不要分级表：构图写死「无分级表」，禁止模型自画空表。成图任一行空单元格 → **不通过**，不得交付。  
- compose/`prompt_builder` 在 `dense_copy` 或已提供 `copy_units` 时校验；缺说明即失败退出。  
- 生图提示词须写死：图内新增文字只能逐字使用准确文案／`copy_units`；说明区无对应文案则留白或删该说明层，**禁止自撰**（自撰是乱码与无依据扩写的直接原因）。

参考这页是氛围或故事页时，允许写成稍长的氛围说明：把已有事实放进真实用得上的场景，使语气有画面；不得为了变长而编造情节。卖点页、参数页仍用标题加说明或表格，不把所有页都写成散文。

文案调性须与商品定位、品牌气质和本套画面定调一致。用户或资料已明确为高端、日常、轻松等时，用词、句式和称呼要贴这一调性，不能写成反差过大的口语、促销腔或书面腔。定位不明时不凭空写成高端或年轻，调性按已有包装、品牌信息和设计方案保持整套统一。可以将已知参数、结构、规格、包装和使用条件转化成有依据的用户利益；不能从结构存在直接推导未经支持的性能。

- 不机械替换商品名，不照抄参考事实。
- 不使用“认真看看”“图示”“实物细节”等无信息增量的填充句。
- 不把已有画面简单重复成文案，例如只写“果皮／红色外观”。
- 参考具体宣称不适用时，优先用本商品另一个有依据的购买理由承接该页面角色。
- 不为填满区域重复卖点或添废话，可因此少字；说明页和卖点模块不得借此删除信息组、削弱说明或改成无说明的单标题。
- 无法形成真实有效内容时标记问题，不编造，也不自行删除该张。

宣传文案不局限于包装转录。学习参考的购买动机、表达节奏和标题力度，结合本商品写原创卖点；不得将不同参考的口感、场景、选择理由等任务一律替换成配料、容量或产品类型。

- 商品事实：参数、配料、规格准确表达，放在必要位置，不反复充当每张核心卖点。
- 场景与情绪：允许符合商品用途的生活场景、情绪和审美表达，不要求每句话都写数字或认证；不能暗含未经支持的性能、健康效果、适用人群或服务承诺。使用场合须有资料或定位依据，不能一遇到场景就写成早餐、午餐、晚餐或一日三餐；一盘鲜果、杯盏等摆法不能当成场合。
- 功能与效果：口感、甜度、营养、工艺、保鲜等具体宣称须有对应依据，不能凭品类常识认定“肯定没事”。

文案交付前同时核对：是否承担原参考类似的购买任务；整套是否在重复配料、容量、NFC等少数事实；是否为消费者自然语言而非“包装信息核对”“产品类型”等内部说明。仅复述画面或填版的句子必须改写或减字。

#### 成图文字读者边界

按读者与用途分，不按「像不像免责」一刀切：

- **禁止印上主图/详情成图**（含小字、角标、页脚）：面向执行者/审核者的过程话术、缺口交代、自检与返修说明。例如「不作虚假包赔与检测数字」「原图未提供纸箱实拍，本页以文字说明为准」「素材模糊通过」「返修备注」「图示仅供参考（执行备注）」等。此类只进交付说明、交付总览或索引。
- **硬禁止上图枚举**（可进交付说明，不可进画面；页脚/角标出现任一类 → 不通过，不得以「字小」放行）：
  - `资料来源`、`来源：`、外链 URL、二维码溯源装饰；
  - `文案溯源`、`文案：`（元标记）、`执行备注`、`准确文案`、`copy_units` 等元标记；
  - `产品保真`、`商品保真`、compose 保真条款原句或其截断拼接（如「产品保真2300m」）；
  - 检测报告编号仿造、无依据营养成分数字。
- **允许上图**：有资料或原图依据、面向消费者的产品说明、用法、保存与必要警示；须写入执行卡图内文案，并入正常版式，不得做成页脚内部备注。
- **拿不准**：默认进交付说明不上图；用户明确要求再上图。

执行卡不得把禁止类句子写入图内文案字段；compose 遇禁词失败；成图审核发现即不通过。

#### 缺素材时的页面策略

- 无纸箱/包装实拍：可用图标＋说明承接，或改该页购买任务；禁止编造包装实拍，禁止把缺图说明写进画面。
- **图标＋说明降级页最低密度**：每个模块必须 **标题 + 不少于 1 句说明**（事实→购买意义）；禁止仅一行短标签撑满大卡。参考信息组数量尽量保留；不够时记录冲突，**不得**交「两大空白圆角框」。审核：大面积留白 + 单行字 → 不通过。
- 无证书/检测源文件：禁止硬留证书/检测**附件壳**（附件一/二展陈版式、报告框）；改为有依据的信息页，或标记该编号内容冲突。
- 供应链/路径页：允许编排「采摘→装箱」等示意链路；须真实可信、标题与步骤与画面自洽；禁止标题是「我方流程」而正文变成买家建议等牛头不对马嘴。**无源实拍时**：只用图标、插画、线框步骤或明显示意拼贴；**禁止**实验室、冷库工人、产线传送带、泡沫托纪实全出血等仿实拍证明感画面。副标若上图须含「示意」或同等披露。不得装成已核验证明材料。

#### 认证与背书外观

- **默认不出**官方/三方认证章图形（含地理标志、有机、具名检测章等「长得像官方」的章面）。
- **例外**：用户或项目模板提供可核验的真章图（路径写入执行卡）→ 仅允许**贴图叠放**该资产，禁止模型重绘章面文字或仿刻边文/星徽。
- **仅有认证名称、无章图资产**：标题/文案可写成立表述（如「丹东草莓地理标志产区」）；可用明显非官方装饰点缀；**禁止 AI 仿官方章**。
- 无依据禁止照搬参考的检测报告展陈、SGS、证书附件壳。

#### 证明/信任页附图与首轮构图

参考为证书/SGS/检测/地理标志章页，或本品须做信任信息页时：

- 生图 design 附图：**不得**使用含证书壳、报告表、公章、SGS 标志的原参考全图；可改用不含章的结构示意，或仅本品白底 + 文字信息卡说明（写在提示词，不附带章面图）。
- 准确文案只列可核实厂名/许可/产地文字；**禁止**营养数值与检测章感图形。
- 首轮构图锁定「圆角信息卡」；**不得**先生成章面再寄望返修抠掉。

参考是检测或证书页时，按上列认证规则、附图策略与缺素材策略承接证明任务，改用本商品可核实内容，不能改成瓶盒合影或单标题海报凑页。参考是用法、冲泡、加热或工艺说明页时，若原做法不能用于本商品，仍须保留“怎么用 / 怎么做”的页面任务，改用本商品能成立的用法、工艺或注意事项，不能改成情景海报，也不能为了像参考而添加蒸汽或编造加热、冲泡方法。参考是营养成分、配料或参数表时，执行卡必须保留表格或同等参数模块，填写本商品真实数据；某一行不成立则保留能成立的行，不能整页改成箱规海报、瓶盒合影或单标题画面。无法成立时记录该编号问题，不静默更换页面类型。

增加参考表达结构对应检查：不仅学习卖点，也学习信息组数、主次关系、字数节奏、并列或递进方式。例如参考为三栏或四格，每项“短标题＋辅助说明”，就为本商品写同等数量、互不重复、可成立的内容，不能擅自缩水成一行两点或一句总标题。卖点模块（三点、四点、标签组、宫格或分栏要点）须保持条目数量及“标题＋说明”，参考有配图则保留“图＋标题＋说明”。参考上的单枚卖点印章或角标也须作为信息位承接，不能当装饰省略或只并进主标题。先寻找真实卖点、场景或决策信息承接各位置；不足时明确记录该区域内容冲突，不填废话、不造证据、不静默删掉信息位。保留信息结构不等于照搬独特措辞、品牌或证明图形。

信息位数量与信息价值同时检查：三个位置必须承担不同且成立的信息，不能以两个同义产地句、同一配料换说法等填满三栏。完整信息结构不是重复填充的理由。

生图前在内部完成整套文案通读，不增加人工确认：遮住图片读全部标题与副文案，检查具体、自然、有购买关联，排除口号堆砌；说明页和卖点模块是否只有短标题；文案调性是否与商品定位和本套定调一致、有无反差过大；场景页场合是否有依据，有无默认成早午晚餐，或把摆法写成了场合。两页文案随意互换仍成立时重写其任务与表达，必要商品身份和规格复现除外。逐图检查参考信息组是否完整，整套检查是否反复复述同一卖点。通过后再交图像制作，不能边生成边随意改词。

### 7.2 按页面任务迁移参考

按该页要完成的购买任务决定迁移尺度，不按它位于主图还是详情目录一刀切。目录仍决定主图或详情的输出规格；页面任务决定要迁移的结构和信息密度。写执行卡须同时使用原图和缓存中已写清的迁移结构；具体提示不能因换气质或场景而丢弃。

- 首屏、氛围、场景类页面：允许重新设计构图、光色、场景和气质，使画面更贴本商品；须保留该页关键信息，如主标题、副标题、规格或同级身份信息。不要求复刻原图排版坐标或纯装饰细节；卖点印章或角标不属于可省略装饰。
- 说明类页面，包括卖点、理由、工艺、成分、故事、参数、证明、用法等：必须迁移该页购买任务、信息层级和模块结构。参考有分栏、宫格、表格、对照或长说明，执行卡须保留相应结构，并写出能把卖点或故事讲完的标题与说明。字号、换行、留白、场景和光色可按商品调整；不能删信息组，不能改写成一张单标题海报，也不能把该页改成另一类画面。
- 场景只可同类，不可原样搬用：参考里能用的生活、氛围、使用或陈列场景，只借鉴场景类型和使用关系，必须重新布置环境、道具、光色和机位，做成类似但不相同的画面。不允许只把参考里的商品换成当前产品，桌面、空间、道具、人物姿态和机位几乎不变。画面中有人物时，不能沿用参考图里的同一个人或同一群人，须换成符合本商品和使用场景的新人物。白底、参数表、证明页本身没有这类场景的，不因此硬加生活场景，也不去复刻参考里的静物布景。说明页改的是画面场景，仍须保住原来的页面任务和模块结构，不能改成另一类海报。
- **跨品类场景三件套**（参考品类≠本品时硬闸；缺一不合格）：  
  1. **场景类型**（从参考借的骨架，如「上天空文案区 + 下半果篮英雄」）；  
  2. **本品环境正向**（背景具体长什么样，如「虚化东港草莓日光温室／草莓植株绿叶，景深浅」）；  
  3. **参考品类点名禁止**（如「禁止橙子、脐橙、柑橘园、橙黄挂果枝头入画」）。  
  禁止策划/提示词只输出「同类重布／户外果篮英雄」这类纯场景类型套话。执行卡 `layout` 与「本张限制」都要看见 2、3，不能只在心里默认。
- **未授权空装饰（按类型禁，不按单词）**：执行卡未点名时，禁止模型自行加**无信息增量空装饰**——传统/国风纹样底纹、线描云纹、卷草、烫金花边、无依据的实心弧形色块外框等。默认 `ornament_motifs: none`（或并入 `extra_chrome: none`）。例外：本张 `extra_chrome`/构图点名，或原参考明确有且要迁移的版式机制。不算空装饰：斜贴卖点、圆角信息卡、卖点章/角标短句、参数表、宫格、项目品牌框壳。「新中式／国风／高端」等风格词**不等于**授权加花。审核出现未授权空装饰 → 不通过。
- 跨页连续结构：参考中前后页为一组连续叙事且后页无独立大标题时，本品不得给后页硬加标题拆开连续关系。
- 同类页模块外壳一致：连续多页若页面任务/模块类型相同（如双场景生活页），执行卡须写 `module_shell: 共享`（框线、标题位、文案带、圆角规格等）。成图前后页互换外壳仍应像同一套；外壳不一致且无记录原因 → 不通过。允许差异时须在执行卡写明原因（如末页改白底参数收束）。
- 对照物（分级/克重页默认纯表）：  
  1. **默认**只保留分级表或文字规格，**不做**钢蹦/直尺/鸡蛋等实物对照。  
  2. 仅当执行卡写明 `physical_scale: true` 且给出对齐方式（`scale_alignment`）时才生成对照图。  
  3. 实物对照须同时满足：对照物与主体同一支撑面、透视一致（禁止钢蹦「立着/歪着」漂在空中）；尺面刻度朝向读者、可读、与克重表同一语义；果/瓶与尺或币有接触或明确对齐线；常识自检——如 15–30g 级草莓相对一元硬币不得呈「巨型道具」感，尺上厘米数须与常见果径同量级。  
  4. 任一不满足 → 不通过；返修**优先删对照改纯表**，不在错误尺币上微调。不得把参考对照（如脐橙配鸡蛋）盲目套到体量不符的本品。
- 同级图标（参数表/对勾列表/保障图标行）：同级、同义、无「重点」语义 → 图标必须同色、同形、同描边粗细、同尺寸。禁止无理由红绿混用、实心/线框混用。仅当执行卡写明某一行为「强调项」时，才允许该行用强调色，且全套规则一致。同级异色无记录 → 不通过。执行卡参数/列表页须 `icon_uniform: true`。
- 元素预算与场景窗数：  
  1. 场景页可写 `prop_whitelist`：仅允许列出的道具，未列出不得生成。  
  2. 说明/参数/信任页默认 `extra_chrome: none`（无来源脚注、无仿章、无装饰尺币、无文件序号圆标——无 `chapter_badge` 时）。  
  3. 多窗/竖叠页：执行卡写 `panel_count`；成图面板数不符 → 不通过。  
  4. 无糖/控糖卖点页：禁止蜂蜜蘸棒、糖块堆等与「无糖」语义冲突的食欲道具，除非文案明确「风味联想非添加糖」。
- 品牌框与非品牌框：店招顶/底栏、外框壳、官方角标壳等为品牌框，颜色不限，禁止临摹参考品牌框；项目内有模板则按 [品牌框模板约定](brand-frame-template.md) 套版及卖点放置表执行。有模板且本张在套用范围时：内容层**禁止**再画任何店招/外框/色边；**审核对象必须是已套框图**；顶栏/底栏压住标题、副标、角标短文或主体关键轮廓 → **不通过**；**标题/副标/角标与商品主体轮廓重叠，或主体顶进标题带 → 不通过**（仅躲开顶底栏不够）；返修默认改执行卡与提示词后**重生**内容层，禁止整图缩小留白塞框。套框后仍见参考色框边 → 不通过。构图、色块、圆角卡、图标排法、卖点章样式等非品牌框，仍可参考样式迁移，但不复制原品牌与标识。
- 使用场合须有依据，不能默认成三餐：使用场合必须来自本品资料、定位，或该页参考里适合本品的使用关系，不能一遇到场景就写成早餐、午餐、晚餐或一日三餐。资料没有餐次依据时，应写成符合本品的具体时刻或用法，例如即饮、冰饮、工作间隙、独处、家庭鲜食或待客分享。参考只是餐桌或配餐画面时，只借鉴使用或分享关系，不自动改成或保留为三餐，除非资料明确支持配餐或某个餐次。同一套里多张场景页，场合要能区分，不能整套都是早午晚；只写“日常”而不落到具体场合，也不够。一盘鲜果、杯盏、桌面陈列这类是画面摆法，不是场合；详情页可以用这种摆法出图，标题和说明仍须写出真正的使用场合，不能把摆法当成场合来写。
- 用法、冲泡、加热或工艺说明页：原做法不能用于本商品时，仍保留“怎么用 / 怎么做”的任务，改用本商品能成立的用法（如冰镇、倾倒、即饮），**到此为止**。**默认不加**加热教程、蒸汽、禁热、请勿加热包装、「以标识为准」式禁热句等文案或画面。**仅当**本页文案与画面仍在讲加热用法，且资料/材质已明确可加热或明确禁加热时，才写对应一句警示并写明依据来源。材质不明：不写死能加热或不能加热，也不用禁热句搪塞。禁止残留参考品类文案（如铝瓶页仍出现 PET 加热教程相关句）。
- 营养成分、配料或参数表：须保留表格或同等参数模块，填写本商品真实数据；某一行不成立则保留能成立的行，不能整页改成箱规海报、瓶盒合影或单标题画面。
- 卖点模块：参考为三点、四点、标签组、宫格或分栏要点时，须保持相同条目数量；每项保留“标题＋说明”，参考有配图则保留“图＋标题＋说明”。不能收成一句总标题，不能只留短标签。卖点落在品牌框还是内容区，以品牌框模板约定中的硬表为准，避免框与内容区重复堆同一卖点。
- 卖点印章或角标：参考上的单枚短句标签（如“匠心熬煮”）也是信息位，即使出现在首屏，也须用本商品能成立的短句承接，不能当装饰省略，也不能只并进主标题；外形和位置不必复刻。宣称不成立时换成同等角色的成立短句，无法成立时记录冲突，不静默删除。成组卖点模块不得只留短标签；单枚印章本来就是短句。印章、斜贴、圆标直径硬上限为画布宽度的20%；辅助文案须明显小于主标题。
- 参考约束的是页面任务、信息层级和模块结构，以及可借鉴的构图骨架与装饰机制。不约束必须复刻的字号和位置，也不允许复制原品牌、标识或原品名。
- 成图与执行卡：须承接执行卡的模块结构与核心文案，允许版式润色（列头、层级、不改义的辅助说明）；禁止改义、丢模块、编造。标题、正文、图示必须说同一件事；文图各说各的即不通过。

### 7.3 保留设计机制

选套后把商品特点、文案主题及参考设计放在一起判断，在逐图策划中协调配色、字体、光影和布局，再形成完整执行卡，不先锁死任一方的风格。当前执行卡style_basis简述商品依据、文案主题、参考可借鉴的构图及色彩关系、最终气质、主辅色各自用途/理由及保留调整项；style保存最终供逐图调用的风格说明，不重复拆文件。文案的商品事实与可用宣称只依据本品资料和证据，逐图内容承接参考购买任务、信息组数及表达力度；视觉与文案可调整换行、字号、层级和排版，但不能减少信息组、削弱标题力度，不能把说明页或卖点模块收成单标题或只剩短标签，也不能为配色或装饰编造卖点、修改事实或省掉必要信息。

生图前逐产品检查理由是否结合商品、文案和参考，而非只说“参考用了这些颜色”或“与包装相容”；同参考多产品也逐个判断，不要求颜色强制不同。没有依据的定位写未知或说明设计选择。配色近似本身不判失败，不因颜色相似自动重生成已通过图片。

逐区检查标题、短条、主体、辅助图案、内框、横条、底栏、遮挡和光影。删除无依据宣称不等于删除其所在区域。用有效内容承接同等任务；确需改变区域时记录原因，不把构图简化成通用模板，也不把说明页改成中央英雄构图或单标题海报。

结合商品、文案和参考共同选择装饰机制：短条形状、圆角、描边、线条粗细、图标和分隔符；强调色、字体气质和光影按最终方案协调。相同功能的装饰复用规则，但外框、圆角卡、弧标题仅用于相应页面，不能变成每张必加的全局模板；参考模块独有且承担明确作用的图形可保留。不为统一而把每张布局做成一样。没有装饰用途时宁可不加，禁止空标签、无指向箭头、无意义色条及错误品类图标。有文案的卖点印章或角标不是无用途装饰，不得省略。不同产品分别判断，不强制共用一套装饰。

#### 字体角色（typeface_policy）

要的是**有依据的字体角色**，不是消灭风格，更不是「全套只能黑体」。刷字、手写感、楷、宋、特形装饰字、英文 display 等都可以用——前提是执行卡 `typeface_policy` 定为某类角色，整套同一规则可复用。

- **信息字**（说明、参数、表格、副文）：优先清晰无衬线，保证可读。  
- **风格字**（主口号、章节大标题、印章/斜贴、气泡短句等）：允许创意字体；在政策里点名用在哪些角色、全套怎么复用。  
- 包装实物字除外，以实物为准。  
- **不要**默认禁止楷/刷字；**不要**把「出现创意字」本身当缺陷。  
- 审核：创意字出现在政策允许的角色上且整套说得出规则 → 通过；同级说明/参数区无规划地乱换族，或创意字只冒出一页、与政策矛盾且说不清 → 不通过。一页问题不自动扩成全套判死。

#### 示意/插画页风格（仅无源实拍的示意页）

无源实拍须用示意/插画时（流程步骤、图标化质控、须标示意的链路等），执行卡填 `illustration_style_id`（可选 `illustration_style_ref` 用户附图）。**不要**用下列风格改实拍主图、白底/透明底、可摄影生活场景、参数表/证书主视觉。

| ID | 名称 | 提示词用描述 |
|---|---|---|
| `flat_sticker` | 扁平描边卡通贴纸风 | 粗细均匀的清晰黑描边；大色块高饱和、少或无真实渐变；贴纸/平面矢量感；体积靠色块与少量网点或平涂阴影；允许可爱拟人小物件；箭头等保持平面图形；整体像商业贴纸插画，一眼可辨为示意 |
| `soft_3d_food` | 软立体食欲商业插画风 | 柔和体积光与光滑理想化材质；食欲向高饱和但干净；轻浅景深；像精修三维食物/静物渲染而非线稿；可有柔和投影；仍是插画，不得做成纪实实拍或产线证明感 |

选用：流程/图标化质控/须强力避免误认实拍 → 偏 `flat_sticker`；吃法摆盘/口感氛围/原料特写示意 → 偏 `soft_3d_food`。先看本页任务再看商品调性；冲突以本页任务为准。同一商品多张示意页默认同一 ID；换 ID 须写原因。用户附图覆盖默认描述。只迁画风，不搬样张题材与文案。样张不必进技能仓库。

每张执行卡至少包括：参考文件与成品编号、用途、目标比例、准确文字、主体类型、商品是否出镜、区域结构、构图与镜头、共同风格约束、产品保真要求、制作方式和验收要点。详情另须写清参考宽高比、候选两档、选定档、取舍理由（见第8.1节硬闸）。可选：`chapter_badge`；同类连续页的 `module_shell`；`typeface_policy`；示意页的 `illustration_style_id`；多窗 `panel_count`；场景 `prop_whitelist`；套框张 `uses_brand_frame`+`safe_area`；对照 `physical_scale`/`scale_alignment`；列表 `icon_uniform`；说明页 `extra_chrome`。`商品保真` / compose 条款仅供执行，**禁止**作为图内文案风格或语气来源，也**禁止**写入准确文案/图内字。

#### 生图提示词段位（写入提示词原文时）

组装后的「完整提示词原文」各段只干一件事；**发给生图模型的必须是白话**，不要把执行卡字段名（如 `panel_count=2`）直接塞进提示词，应译成「上下两窗」「与详情09同一套外壳」等句子。

| 段 | 只写 | 不写 |
|---|---|---|
| 商品核对 | 六类各一句 + 硬要求写一遍（compose 默认生成） | 英文字段整表；保真条款全文（除非 legacy 开关） |
| 本产品风格 | 本张气质、配色、字体、光影；**仅本张用得上的装饰** | 全套装饰菜单；窗数与文案正文；仿章禁令（放限制） |
| 本张构图 | 模块结构、区域、几窗、道具边界、安全区、同壳约定（白话） | 禁词枚举；完整上图文案 |
| 上图文字 / 分位 | 要印上图的字 | 构图说明；风格菜单 |
| 本张限制 | **不要做什么**（含仿官方章等） | 「必须两窗」等正向构图；店招禁令（仅主图01有模板时写） |

硬规则：

1. **本张装饰**：style 禁止把整套装饰词库抄进每一页；本张不用的机制不要出现。这只限制装饰词库抄袭，**不得**理解成「构图/限制也可以只写三个字同类重布」。  
2. **文案不双写**：已有 `copy_units` 时，提示词只保留上图文字分位，不再重复一整段摘要。  
3. **分级默认纯表**：未开实物对照时，构图白话**不得**点名硬币/直尺/钢蹦；需要对照时执行卡先开 `physical_scale` 并写对齐方式，再在构图里用白话描述。  
4. **店招＝品牌框**（顶/底栏、外框壳等身份层，不是圆角卡/图标等普通装饰）：禁临摹仅主图01有模板套框时写入；其他页默认不写。套框张限制段另加：标题带与商品之间留清晰间隔，禁止果/瓶顶入标题字。  
5. **identity_check**：按需附图，不默认每张三图。  
6. **输出规格**：主图写 `1000×1000px，1:1`；详情写本张选定比例与目标像素；有离散 aspect 映射时另记实际传入档。「无独立宽高参数」等元话不进生图正文。  
7. **减肥不可删**：短「商品核对」只压缩观察表/保真长文的呈现；**不授权**删减：跨品类三件套、本张输出规格（主图 1:1／详情选定档与目标 px）、完整 `copy_units` 分位、模块数量与结构迁移要求。只写「同类重布」、省略本张比例取舍、或主图用「同上」跳过落盘 → 不合格。  
8. **发送前自检**（Agent 勾选，**不另开审核阶段**）：段位、分位双写、尺币、本张装饰、白话展开；跨品类三件套；详情比例四字段；**主图／详情落盘提示词非空**。不通过则改执行卡后重新 compose。成图对错以第10节看图为准。

另列主产品素材、出镜面和辅助核对素材：正面、背面、侧面或局部各司其职。正面识别图不得把背标当正标；多素材不能拼成不存在的混合标签。执行卡同时列参考信息组与本商品文字的逐组对应，以及使用的统一装饰规则。

每张制作提示词须自包含：该张适用的产品锁定、**本张**风格与构图、准确文字、参考职责及禁止项，不使用“同上”代替，不把全套装饰菜单塞进每张。制作时同时提供对应参考原图与匹配的已验收高清产品素材，不依赖聊天记忆传递风格。

商品可以必须出现、可选出现或不出现。辅助图案可以独立承担主视觉，但不得暗示未经支持的工艺、营养或功效。

## 8. 第五步：确定尺寸及平台核验

### 8.1 详情最终制作规格

- 详情生成目标宽900px，目标高度最高1600px，即目标画幅最多细长至9:16。该上限约束策划及生成要求，不作为实际原件直接淘汰的硬门槛。
- 逐张读取参考实际宽高，计算比例，从下表选择最接近的常见比例。
- 比例接近程度使用 |ln(目标宽高比/参考宽高比)| 比较；两个相邻候选的接近程度相同或相差不大时，优先选择高度更大、更竖长的画幅。
- 比9:16更细长的参考按9:16重新组织；不拉伸、不直接裁断内容，不擅自拆屏或减少内容。确实无法容纳时记录具体冲突，不伪称完成。

| 目标宽:高 | 目标像素（宽×高） |
|---|---|
| 16:9 | 900×506 |
| 4:3 | 900×675 |
| 1:1 | 900×900 |
| 4:5 | 900×1125 |
| 3:4 | 900×1200 |
| 2:3 | 900×1350 |
| 9:16 | 900×1600 |

**执行硬闸（不改上列选比例口径，只堵偷工）**：

1. **禁止整套详情默认同一比例**。每张必须按本张参考独立选档；多张偶然同档可以，但不得未读参考就全套填 3:4 或全套填 9:16。  
2. 每张执行卡须写清：**参考宽高比**、**候选两档**、**选定档**、**取舍理由**（含为何不选另一档）。缺任一项 → 不得 compose、不得生图。  
3. **不得**把尺寸规则简化写成「详情只用 3:4 或 9:16」；常见比例表七档均可成为选定档。  
4. 宿主工具若只有离散 aspect（如仅 1:1 / 3:4 / 9:16）：先按上表选定**目标档**并写入提示词目标像素 → 再映射到工具可传的**最接近档** → 在调用参数与生图提示词留存中**同时记录「目标档」与「实际传入档」**。禁止把映射偷换成全套 3:4；禁止只记传入档、抹掉目标档。

保持原参考的视觉层级、主体关系和信息区域，按选定画幅适当重排。整套靠配色、字体、光影和图形语言统一，不要求高度相同。

详情策划仍按参考选取最近常见比例并写入提示词；期望原生宽与白底 2400 目标并列写入执行卡（营销详情期望原生宽约 900，最高画幅约 900×1600）。宿主尺寸分两层：

- **A. 宿主硬上限**：当前工具/档位无法更高 → 记录能力上限，允许上采样至交付宽 900，**不空耗返修**。
- **B. 同工具可出更大却未取**：接口有更高尺寸/模型档时须优先更高原生，不得默认最低档（如仅因方便取 720 宽）。

详情审核与返修不因像素或比例未命中目标表判失败（工具硬上限时），也不因此触发返修。原生宽明显低于期望且属「能升未升」时，在交付说明标质量风险，**不得标成高清**。明显构图破坏、信息遗漏或页面任务偏移仍按参考迁移问题处理。交付将选中图片等比缩放至900px宽；交付说明强制写：原生宽高、是否上采样、宿主档位；有离散 aspect 映射时另写目标档与实际传入档。不得为匹配表格裁内容、拉伸、拉边填充、补空白或重新设计。

### 8.2 数量与容量

- 制作不设单文件容量上限，不为凑1MB、3MB等目标牺牲画质。
- 不设置主图或详情图制作数量上限。所选套系主图几张就制作几张主图，详情几张就制作几张详情。
- 不自动去重、精简、合并、跳过或增加设计页面；资料冲突记录到对应编号。
- 主图生成目标及交付尺寸1000×1000px、1:1。正方形原件等比缩放至1000×1000；非正方形不能直接拉伸成方图，应检查构图并在必要返修范围内处理。详情尺寸放宽规则不自动套用于主图。
- **主图执行硬闸（比例固定，仍禁偷工）**：主图不做详情七档选比，但每张仍须独立执行卡与完整提示词落盘；输出规格写死 `1000×1000px，1:1`；禁止「同上／见详情／见01」冒充本张原文；禁止跳过 compose 直接生图；有离散 aspect 时传入档须为 1:1（或工具等价方图档），并在留存记「目标档=1:1」与「实际传入档」。套框张另遵守品牌框约定，不得因「反正是方图」省略安全区／有效内容宽高%。
- 不把低分辨率上采样称为原生高清；记录实际原生生成尺寸及导出尺寸。

### 8.3 平台要求单独记录

核验具体平台、类目、店铺类型和图片入口的尺寸、格式、容量及数量限制，记录官方来源、日期及未核验项。

本节尺寸是用户确定的制作规格，不是四平台已核验共同上传标准。平台限制不用于减少设计数量或压低母版画质；存在冲突单列，不承诺全部直接通用。

本次默认交付完整制作文件，不自动生成上传切片或多套压缩版。后续明确需要上传适配时，再从同一内容生成必要切片、压缩或尺寸适配，保留原制作文件。

内容审查独立执行：参考中的认证章、检测图、数据、工艺及承诺不能只换商品名称照搬。

## 9. 第六步：逐图完整制作

每张输入明确区分：

1. 本张原参考：控制构图、镜头、区域关系、层次和遮挡。
2. 套系共同规范：控制配色关系、字体层级、光影、材质和图形语言。
3. 第二步已验收的本产品高清白底／透明底素材：作为实际产品输入，控制真实形状、比例、颜色、Logo、包装及内容物；原始照片仅作真实性与细节复核，缺视角先补做预处理。
4. 本张准确文案：唯一允许新增的文字。

直接读取对应原参考，不只依赖文字概括。不默认把生成首图传给所有后续任务，不只参考上一张。内部基准只继承已通过维度，不传播布局和产品错误。

默认一次生成完整参考迁移画面，轻量检查后直接采用生成原件。制作前完成准确文案与布局安排，不默认在生成后准确排字、换瓶、贴标签、改背景或重新排版；不得自动降级为“原照片裁块＋底色＋通用标题”或摄影内框卡片。需要返修时仍由 poster-style-transfer 负责，按第10节执行。

主图若用户指令提供 `模板：`：须已在启动阶段通过模板校验（壳 `shell_alpha` 合格），且框上填字所需 slots 已锁定。默认只套**主图01**。顺序见 [品牌框模板约定](brand-frame-template.md)：内容层**一次生成**进有效内容区（提示词用百分比写清有效宽%/高%与四边留白，勿只写「进安全区」；标题不得压商品）→ **审核前先套框** → 压栏/压主体与融合问题一并返修（默认改提示词重生内容层，或改 texts）→ 再套框交付。**禁止**整图缩小/留白缩进硬凑塞框当交付。不在生图步让模型画店招框。无模板不临摹参考品牌框，不将该页标成待套版。

使用第二步已完成的高清白底与透明底素材辅助保真制作；无透明底能力而未做透明底时，不得假称已有透明底。它们不是固定的最终设计方式，不要求全套重复同一抠图或视角；原图始终保留。

生成前明确目标比例及像素尺寸，单位写px；每张提示词仅在输出规格处写一次，布局段不再重复不同画幅要求。当前工具没有独立宽高或比例参数时如实说明，不能将文字要求当成硬性控制。记录原件实际像素和比例；主图按1:1等比导出1000×1000，详情按放宽规则保留选中版本实际比例并等比导出900px宽。等比缩放只调整整图像素大小，不改变设计；不足目标宽度时可等比放大，须注明上采样，不称新增高清。禁止拉伸、裁内容、拉边填充或重排来凑规格。

### 实际调用记录

**落盘与 compose 硬闸**（白底／透明底／主图／详情／返修均适用）：

1. 每次调用生图前，必须先把**实际将发送的完整提示词原文**写入  
   `工作文件/<产品>/生图提示词/<白底|透明底|主图|详情>/<编号>_初始.md`  
   （返修用 `<编号>_返修01.md`）；再发送**同一字符串**。  
2. 禁止只把短句写在工具参数里却不落盘；禁止用「同上／见执行卡／摘要」冒充原文；不能保存未展开变量或仅文档路径。  
3. **对应编号的提示词落盘文件不存在或内容为空 → 禁止调用生图工具**。  
4. **新增营销图（主图＋详情）／返修默认必须先走 compose**（`project_files.py` compose + `prompt_builder.py` 读取校验）通过后，才允许调用生图；密文页 `dense_copy` + 完整 `copy_units` 未齐 → 不得 compose、不得生图。详情缺比例四字段同拦；主图缺本张输出规格（1000×1000／1:1）或落盘空文件同拦。  
5. 白底／透明底亦须落盘完整提示词后再调用；可不走营销 compose 字段全集，但仍禁止空文件／「同上」冒充。

固定商品保真条款不能在执行中概括或删减；跨品类三件套、本张输出规格、`copy_units` 分位、模块结构等执行卡硬约束不得当冗余删掉。字段缺失、不明项无原因、缺实际商品附图时先补齐；仅原图编辑例外才须有 `edit_target`。不绕过入口。已有prompt操作可留存外来真实历史调用，不用它替代新增任务的compose检查。完整规则、字段和不出镜例外见组装说明。

涉及输出尺寸的文字要求必须包含在实际提示词中（详情含选定档目标 px）；有离散 aspect 映射时同一留存文件记「目标档」与「实际传入档」。透明底紧凑裁边、返修保持原画幅等情况按真实任务写，不强塞营销图尺寸。

同一文件另记图片编号、用途、工具名、实际附图的顺序与职责，以及真实传入的参数和值。接口若不提供独立尺寸参数，明确记录“尺寸要求仅写入提示词，无独立尺寸参数”，不能将900×1600等文字要求伪记为已传入的宽高参数。不存密钥、令牌或其他认证信息。

调用前状态为待发送；调用后如实登记已发送、失败或受阻，有实际返回时关联对应输出及工具返回的任务标识（若提供）。工具自行返回的修订提示词与发送原文分开记录，不覆盖原文。调用前临时修改提示词时先同步待发送原文，确保保存内容与真实发送内容一致；归档失败时先解决记录问题再调用，不先生成后凭记忆补写。提示词文件留工作目录，不混入成品交付。

场景与商品事实一致：明确产地的页面避免引入与该产地明显不符的地貌或建筑；原料及内容物颜色须对照真实资料。场景创意不得伪装成原料来源、生产工艺或真实性证明。

生成原件是默认设计版本：轻量检查通过后只作本节允许的等比尺寸导出和编号命名，不额外制作另一套设计。只有确实改善整体质量的一轮返修版才可替代原件，不因文件更新或像素更接近目标就自动选返修版。工作目录原样保留原件，分别记录原生与交付尺寸，不把上采样称为原生高清。第二步白底2400×2400及透明底有效像素规则不随营销成品宽度调整。

生成工具返回图片后，立即复制原件到“工作文件/产品名称/生成原件”，以对应编号登记实际路径与任务状态，再开始审查，不等整套交付才保存。工具默认目录不能作为唯一工作存档。修复返回图保存到“修复版本”，保留初版，不覆盖。正在生成、尚未返回时只记录运行状态；保存失败须标明实际位置并处理，不能假称已存入工作目录。通过后复制到交付目录，工作原件仍保留。

## 10. 第七步：轻量检查与必要返修

### 同张图片一次查齐，汇总后返修

每张原件返回后，先对照真实商品素材、执行卡和对应原参考，完整检查商品结构/比例/标签信息、准确新增文案、构图机制及画面完整性，将本张全部实质问题集中写入一份review，再决定是否生成返修。不先修标题，返回后才开始检查同张商品标签；也不因“轻量”而跳过商品局部核对。不必等待所有图收齐才审核，可按已返回图片的小批处理，但每张都完成完整检查。

review按商品与标签、文案、参考构图、完整性分别记录结论和问题位置，不用一个总分或“整体不错”代替。需要返修时一次合并该张所有必要问题，并锁定已正确部分。返修返回后对照原件和商品基准复核目标问题及新增退步；后续确实发现先前漏检的实质问题须如实登记，不因“已查过”放行，也不以重新拆问题绕过返修额度。

不再启动默认的重后处理链路。detail-flow仅作轻量成图审查：检查明显问题，不重新设计或为完美化小字破坏画面。原件优先不等于所有原件自动通过。

轻量审核只减少无必要的后处理，不降低参考迁移要求。每张原件须直接对照自己的原参考和执行卡，明确检查：

1. 主体类型是否正确：原料、商品、场景、说明或参数页不能被擅自改成另一种页面。
2. 主要构图机制是否落实：主体尺度、微距关系、前后遮挡、标题层级、主要信息区域与图形机制不能仅剩配色相似。
3. 页面表达任务是否一致：原料页不能变商品识别页，解释页不能变首屏海报。
4. 说明页和卖点模块是否仍是标题加说明，有没有收成单标题海报；卖点模块条目是否还在，印章或角标有没有被丢掉。
5. 场景是否只做成同类：有没有只换商品、把参考场景原样搬来；人物是不是参考里的同一个人或同一群人；跨品类背景作物是否本品，有无参考品类残留（如草莓页挂橙）。
6. 使用场合是否有依据：有没有默认写成早餐、午餐、晚餐或一日三餐；有没有把一盘鲜果、杯盏等摆法写成场合。
7. 文案调性是否与商品定位和本套定调一致，有无反差过大。
8. 成图有无内部过程/缺口/自检话术；缺包装或证书时有无伪造实拍或硬留附件壳；图标降级页是否大面积留白＋单行字。
9. 标题、正文、图示是否说同一件事；路径页是否自洽；有无参考品类残留句。
10. 场景是否只换产品；跨页连续是否被错误加标题拆开；对照：有尺币是否共面可读且比例常识成立，否则应纯表（默认无实物对照）。
11. 印章直径是否超过画布宽20%；辅助字是否抢主标题；有无 AI 仿官方章；章内乱码或不核验 → 不通过。
12. 品牌框：**必须看已套框图**（不是内容层 alone）；顶/底栏是否压住标题、副标、角标短文或主体关键轮廓 → 压字不通过；**标题/角标是否与主体重叠** → 重叠不通过；内容层是否仍画色边/店招；卖点是否符合硬表；融合是否「场景完整、框自然压边」；有无整图缩小缩进硬凑 → 硬凑不通过。
13. 本页未讲加热却出现禁热句/蒸汽 → 不通过；无源却仿纪实供应链证明感 → 不通过。示意页是否符合所选 `illustration_style_id`。
14. `chapter_badge`：圆标数字须与执行卡一致；无该字段却印文件序号 → 不通过。
15. 图内语气是否像质检/保真报告腔（内部术语外溢）→ 不通过。
16. **密文页／表行**：必须**逐格**对照执行卡／`copy_units` 读完；任一格乱码、漏句、与准确文案不符、无依据扩写、**表体空行** → 不通过。不得用「整体不错」放行。
17. 同类页 `module_shell`：前后同任务页外壳是否一致；无原因的不一致 → 不通过。
18. 字体：对照 `typeface_policy`；同级信息无规划乱换族，或创意字与政策矛盾 → 不通过；政策内风格字（含楷/刷字）不单独判死。
19. **不可跳过样例**：页脚/角标有无 `资料来源`/URL/`文案溯源`/`产品保真`？同级图标是否同色同形？多窗 `panel_count` 是否一致？道具是否超白名单或与卖点语义冲突（如无糖旁蜂蜜蘸棒）？信任页是否仍出章面/检测壳？**有无未授权空装饰（云纹/卷草/无依据色块外框等）？说明区空白却留大模块壳？返修后是否新增与本品无关的道具/果材？**任一项否 → 本张不通过；不得「整体氛围好」放行。

以上各项均落实且其他轻量检查通过，才直接交付原件；任何一项有实质偏离，属于参考迁移问题，触发 poster-style-transfer 的一轮必要返修，不能因为原件漂亮、文字正确就放行。对照失败优先改纯表；乱码/来源脚注整段删除，不得美化保留。例如商品A主图03：参考和执行卡要求巨大原料微距，初版却用大油壶占据中心，应返修回原料主视觉；移除油壶、恢复原料尺度及信息层级的修复版更符合参考，应优先选用。此为纠正页面角色，不是无必要的美化。

已有原件与修复版时逐张比较，选择商品与文字无明显错误、页面角色和参考机制更准确、整体构图与融合更好的版本。不得固定只选原件或只选最后修改版本；效果相近时保留原件。没有实质偏离且无需返修的，不为产生比较版本而额外生成。

检查：

- 数量与编号是否逐张对应，是否有遗漏、擅自精简。
- 产品、SKU、颜色、结构、Logo、包装、配件及内容物是否准确。
- 卖点是否有依据、有信息增量，是否混入参考文案或无用填充。
- 说明页是否收成单标题，卖点模块和印章是否完整；场景是否原样搬用、人物是否与参考同一拨人；场合是否默认成早午晚餐，或把摆法写成了场合；文案调性是否明显偏离定位。
- 构图力度、标题尺度、主体关系、遮挡、区域结构是否落实。
- 套系视觉是否一致，各张是否符合自己的参考角色。
- 是否在生成前按参考选取最近常见比例写入提示词，并在接近程度差不多时优先更高画幅、目标最高9:16；主图交付1000×1000，详情等比导出宽900。详情不因像素/比例未命中目标表判失败或返修；重点检查完整构图、参考机制及手机端可读性。
- 文件格式、容量记录、数量和完整性。容量只记录，不作为制作淘汰门槛，不自动压缩。详情像素尺寸不作为审核淘汰门槛。
- **执行合规抽查（交付前）**：**主图与详情**每张是否有非空落盘提示词；主图输出规格是否为 1000×1000／1:1 且非「同上」冒充；详情执行卡是否有逐张比例四字段（参考宽高比、候选两档、选定档、取舍理由）。若主图缺落盘／跳过 compose，或全套详情同一比例且未写取舍理由 → **视为执行失败项**，须补记或返工受影响张，不得假装合规。

内部查看每张原件及包含候选图的有序审查预览，不用自评分、提示词或脚本检查替代看图。内部审查预览留在工作目录，不作为交付预览；交付预览只含通过项。

### 10.1 包装文字：先核对源素材，再判定成图问题

对每个问题区域先查看该产品全部相关原图，区分源素材限制和制作新增错误，不能仅凭瓶身小字无法读清就判失败。

| 情况 | 判定与处理 |
|---|---|
| 原图清楚，成图改错、漏字、乱码或明显变糊 | 制作问题，定向修复 |
| 所有相关原图本身模糊，成图保持相近状态，未明显改写 | 素材限制；不单凭小字无法辨认卡住交付，不要求模型猜字补字 |
| 原图模糊，成图却新增明显乱码、虚构文字或改变标签结构 | 制作问题；原图模糊不能作为免责理由 |
| 原图能确认的品牌、品名、规格等被改错 | 必须修复，不因其他小字模糊放行 |
| 平台要求清晰展示的必要标签资料缺失 | 单列上传资料缺口，不与营销图片设计验收混为一谈，也不保证可直接发布 |

不得将源图不可读的小字自行识别成确定文字，也不得以“手机端看不清”放行可确认的生成错误。其他检查通过且仅有源图固有模糊的，按“素材模糊通过”交付。必须在交付说明中逐项列出这些图片的编号和模糊位置，例如“主图03：原图瓶身底部小字模糊，保持原素材状态，按素材模糊通过”。不能仅写一句笼统的“原图部分模糊”，也不能漏列对应编号。此放行不适用于生成新增的错字、乱码、标签结构改变或其他制作错误。

### 10.2 逐张完成返修闭环

只有错商品、可确认的错容量或包装、明显乱码、无依据宣传、必要内容遗漏或明显参考迁移失败等问题触发必要返修。原图固有模糊、单纯像素规格差异或没有实质影响的小瑕疵，不自动触发。

**默认路径（改提示词重生）**：

1. 先改执行卡（文案／构图／限制／`copy_units`）：多了什么写进禁止，少了什么补进必须包含。  
2. 再 compose，写出 `<编号>_返修01.md` 完整新提示词（须显式含「禁止增加：…」「必须包含：…」）。  
3. 用新提示词**重新生成**（仍附原参考 + 白底素材；失败原图仅可作反例说明，**不作默认编辑底图**）。仍走 poster-style-transfer 的生成职责。  
4. 禁止「只改像素、不改提示词」却声称已按规范返修。

**例外（原图编辑）**：仅当问题是极局部且文案/结构已正确（如单处脏点）时，才允许以原生成图为 `edit_target` 定向编辑；review 须写明例外理由。禁止为修标签删标题、改变整体光影、添加摄影内框或拉伸边缘；不是重新套模板或由独立脚本换瓶排版。

返修后必须并排比较原件与返修版：目标问题是否解决，是否新增商品或文字错误、无关道具/果材，是否丢内容，整体构图与场景融合是否退步。只有解决问题且未明显退步，才采用返修版；否则保留原件作为最佳候选，并按实际问题记录未通过，不能选更差版本充当修好。默认只交通过项；用户另行要求交候选时提供最佳候选并说明问题，放行不自动改尺寸约定或审核结论。若该张需品牌框套用（默认主图01），审核与返修均在**已套框**画面上判断问题；返修重生内容层或改框上文案后须**重新套框**再验收，通过后才导出交付。

自动执行范围须在新任务中明确授权：初始整套制作，每张最多一轮必要定向生成或修复，不逐次确认；仍受用户明确的总次数及费用上限约束，不包含购买服务、开通账户或另用收费API。初次生成不算返修。一轮指汇总该张审查问题、完成一组定向修改并复查；同一轮可以处理多处问题，但不得以同一轮名义连续进行多次模型修复尝试。读取、复制、命名、尺寸检查和预览生成不消耗返修轮次。该轮复查仍失败则标记未交付，不自动开始第二轮；超出范围或能力阻断才询问。

每张独立记录问题、触发理由、返修次数、版本来源和选版结果。有明显问题且具备能力、仍在一轮授权内时完成必要返修，不只登记失败；没有实质问题则直接交原件，不为了用额度而修。某张用完额度不影响其他图片；返修后仍有明显问题、存在真实阻断或用户停止时列未交付。总控查看实际选用文件，不能只读报告或以“最新文件”选版；两类交付预览必须来自同一批最终选用图片。

```text
交付/

    产品素材/高清白底、透明底
    主图/
    详情/
    主图预览.jpg
    详情图预览.jpg
    交付说明.txt
工作文件/
  _临时/                         # 清单、payload、临时脚本，成功无依赖后清理
  产品A/
    product.json                  # 状态、选版、审核与必要检查结论
    执行卡.json                   # 当前文案、风格、观察表及逐图设计
    处理素材/
      高清白底/                   # 白底初版及其返修版，按视角编号
      透明底/                     # 透明底初版及其返修版，按视角编号
    生成原件/
      主图/
      详情/
    生图提示词/
      白底/
      透明底/
      主图/
      详情/
    修复版本/                     # 仅营销图发生返修时创建
      主图/
      详情/
```

上方是本轮固定归档结构，产品目录名在初始化时确定并记入project.json，所有路径从同一产品索引定位，不在产品名和ID之间另建两套目录。生图提示词统一使用此名称，不另建“生成提示词”等同义目录。按实际任务创建有内容的子目录，不制造空占位目录。白底/透明底图只进处理素材，营销图初版只进生成原件，营销图返修只进修复版本，实际提示词只进生图提示词；不得把这些PNG、提示词或临时清单散放在产品目录顶层。文件返回立即按此归档，不等收尾才整理。确有必要保留的额外证据附件按索引引用存放，不默认再建输入与参考索引、待修文件、执行与审查记录等目录。

收尾时核对本轮各文件的分类路径和索引引用；发现本轮文件放错位置，移动前检查目标无冲突及无运行任务依赖，移动后更新并验证索引、执行卡等引用。实际调用提示词及其参数原文不改写；其中记录的历史绝对输入路径不伪造替换，必要时在产品索引记录迁移关系。无法安全整理时保留原处并披露，不制造第二份“最终版”。旧项目不自动搬动。

交付目录包含通过审核的高清白底与透明底产品素材、主图、详情、主图预览、详情图预览和简短说明；不再交付一张混合主图与详情的全套预览。不要求所有参考编号出现在交付预览中。图片保留对应参考编号，不为补齐序号混入失败稿，也不将失败图重新编号隐藏缺项。不自动添加上传切片或压缩版本。

### 交付根目录总览

每次完成导出交付，必须生成或更新 `交付/交付总览.md`，单产品和多产品均适用。用户只打开这一份即可知道所有产品的主图（头图）、详情图哪些已交付、哪些未交付及原因，不以各产品说明或聊天回复代替。总览是产品索引与实际文件的汇总视图，不另建汇总JSON。

- 顶部注明更新时间、处理范围、图片类别及整体状态（齐全、部分交付或尚无交付）；覆盖项目内已登记的全部产品及各自计划范围，包括完全受阻、没有建立交付子目录的产品。单独返修后同步受影响行，不把未处理产品漏掉或重复计入本轮新增数量。
- 第一张表每产品一行，列产品名、主图已交付/应交付、详情已交付/应交付、缺失或待更新编号、产品交付目录链接。每格直接列出缺失编号，不能只写“部分失败，见各自说明”；数量多时在表后按产品展开，入口处须能定位。
- 接着列异常明细：产品、类别、编号、状态、具体原因、下一步或所缺输入。未生成、生成失败、审核未通过、导出失败、已丢失或待更新分别写明；不能用“未通过”笼统代替原因。没有异常时明确写“主图和详情图无缺失项”。
- 素材缺失与主图/详情缺失分开：另列未交付的白底、透明底视角及原因，以及缺失预览、素材模糊通过和实际影响上传的限制；素材未交付但营销图齐全时，不把营销图写成缺图。没有素材或预览任务时不列为失败。
- 汇总前以各产品已选参考编号和任务范围确定应交付集合，逐项核对索引状态、当前选版与交付文件真实存在且可读；不能只数文件、只信 `passed` 或把旧交付当新版本。只做详情时，主图写“不在范围”，不列为缺失；同名SKU分别列明。状态不明或计划缺失时写“待核实”，不得猜成零张或齐全。
- 交付前抽查**主图与详情**落盘提示词，以及详情比例取舍（见第10节执行合规抽查）；主图缺落盘／跳 compose、详情缺四字段、或全套同比例无理由 → 在总览异常明细标执行失败／待补记，不得写成已合规交付。
- 总览使用相对 `交付/` 的链接，文件名含空格时正确转义；不存在的交付目录不做假链接。写入临时文件后核对数量与编号，再更新同一份总览，不积累多个“最终总览”。最终回复优先链接总览，再说明主要未完成项。总览不触发生图、补图或额外返修，不代替实际成品。

## 12. 执行与完成边界

生成提交、文件归档、状态登记按固定工具批量处理，读取清单后再执行；需要看图判断的依赖保持顺序，不能把未审核图自动标为passed。批次报告某项失败时，核对已有实际结果，只恢复失败和未执行项，不盲目整批重试。工具已返回成功但解析或归档失败时，先找该调用的真实返回文件，不因此重新生图。
